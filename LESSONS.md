# LESSONS.md: what was tried, what failed, and the rules that follow

This file is the project's memory of the H-infinity co-design tool (controller plus actuator/sensor placement). It covers the Ginzburg-Landau (GL) phase in STAGE0-6.md and the backward-facing step (BFS) in BFS.md. For each attempt it records what was tried, what failed and why, the bugs found, and the rules that follow. Its purpose is that nobody, human or AI, proposes again something already rejected, or brings back a bug that was fixed. It was compiled on 2026-10-14 from STAGE0, STAGE1, STAGE1B, STAGE2, STAGE3, STAGE5, STAGE6, TRACKER, CLEANUP and BFS.md (code version 20261010h, branch claude/exciting-pasteur-3ocffp). A few points were checked against the current tree and against the 20261010g logs (jobs 770628-770633); those are marked "checked 2026-10-14". A review on the same day re-read the 20261010g logs, the record JSON and NPZ files (runs/*/K_B_C_*.json, _part1.json, *.npz, post.json) and the code; entries it changed carry "(corrected 2026-10-14)". A second pass the same day restructured the file. It moved the 20261010g run figures into one dated section (§20), gave every "Do not repeat" entry an evidence tag, added the reading checklist below, added "Current code:" lines where the code contradicts a rule, added the lessons of the 20261010g post mortem (§19, from the analyses in the session scratchpad an/*.md), and turned §17 into a refactor inventory. Later that day the four analyses whose verifiers had failed on a session limit (missed-peaks, strip-ab, omega-growth, origin-github) and gate-refusal were regenerated with VERDICT lines and VERIFIER sections; §19, §20 and the entries that cite them follow the verifiers. STATUS.md gives the one-line state of each item; this file gives the reasons.

## How to use

1. **Before you propose or build a change, search this file** (grep) for the topic, the flag name and the mechanism. Then grep STATUS.md, the STAGE*.md files and BFS.md.
2. An entry marked **(superseded: ...)** says what replaced it. Do not revive the old idea without reading the replacement.
3. **Do not repeat** entries record measured negative results. To reopen one, state a new mechanism or a changed premise explicitly.
4. Source pointers: `[STAGE5 §28 l.1437-1454]` means file, section and lines. `TRACKER l.n` means TRACKER.md line n. Code pointers (`file.py:line`) were valid on 2026-10-14 and will drift, so cite the function name as well.
5. **(inference)** marks a reading that was not measured. **(ambiguous)** marks a point where the sources disagree.
6. To add a lesson, put it under its topic and mark the entries it supersedes rather than deleting them. Also add an ERRATA note in the file where the original claim was made.
7. **Evidence tags (added 2026-10-14).** Every "Do not repeat" entry carries one or more tags, judged from the entry's own evidence and sources. **[clean A/B]**: the arms share the parent or start and the code, and differ in one switch (one case is enough for the tag; replication is noted where it exists). **[single pair]**: one with/without or before/after comparison on one case whose control is not documented as one switch from one parent (a single replay, two runs at different settings, one dumped QP). **[confounded]**: the compared arms differ in more than the switch under test (parent, code version, budget, resume state). **[mechanism only]**: no comparison; a diagnosed mechanism, a code reading, a reproduced bug or a decision. A weak tag does not make a rule wrong; it says what reopening it would need.
8. **"Current code:" lines** say where the code, as checked on the date given, contradicts or qualifies the rule above them. They describe the code, not a decision, and go stale with the code: re-check before acting on one.
9. **§20 is a snapshot** of the 20261010g runs (values, poles, positions, ledgers). Topic sections keep mechanisms and rules and point to §20 for the numbers. Replace §20 when the next batch is read; move what it teaches into the topic sections or §19.

Glossary: *frozen path* means GL case B at ne=100 with the code defaults, gamma 10.23128516441147 in the environments of STAGE0-6 and BFS.md; the last digits depend on the numpy/BLAS build (10.231285164411261 in the 2026-10-14 conda-forge sandbox environment, §19), so the bit-identity test compares against the unchanged code in the same environment (revised 2026-10-14). *Nominal* means the flags passed by tools/n100_kbc.sh, tools/n200_kbc.sh and bfs/run_bfs.sh; the code defaults are the frozen path. *Test plant* means the BFS coarse mesh, n = 33,593; the *full mesh* is n = 191,720. "Lattice" has two meanings: the case-nesting lattice (tools/lattice.py, tools/lattice_check.py) and the BFS full-model frequency lattice (lattice.py, `--oracle lattice`).

## Reading a run before quoting a value

Added 2026-10-14, after the review of 20261010g found three wrong log readings in this file. Check these in order before quoting a value from a BFS run, and quote log lines verbatim, best= included.

1. **The "outer k: ... best=" line.** It alone says whether the round was accepted (best equals the certified value) or not (best keeps the earlier value). The diagnosis lines are not verdicts: "refusal: witness ..." is printed whenever certified > t (1 + 10 rtol), accepted or not (§2). The uncommitted stage-A edits of 20261010j split it into "t lag" / "missed peak" / "within tol".
2. **Per-round termination_code, stat_value and inner_iters from the record JSON** (history; the _part1.json of a continued run). Code 4 is the budget, not convergence (§1). Code 0 under `--sqp-stat rel`, the SISO default, is not stationarity (§14).
3. **On a continued run, the "resume:" line** ("resume: inner budget N, SQP trust X, K peak members restored") or at least the checkpoint line. Without "resume:", a CONTINUE=1 from a finished record restarted the inner budget at `--inner-maxit` and dropped the SQP trust radius and the followed peak set. That happened in five of the six 20261010g jobs (§15, §19). Checked 2026-10-14: HEAD ad580e3, labelled 20261010j, and the stage-A working tree still write no maxit_cur, sqp_trust or peakset into the record. Until a version does, assume the loss for any continuation of a finished record. A deadline-stopped run keeps its checkpoint and restores them.
4. **The sigma_2 enrolment line** ("sigma2 enrolled at N of M frequencies"). At 0, the Clarke-block and sigma_2 machinery was idle and the GL kink mechanisms do not apply (§4).
5. **The compensator poles and the closed-loop alpha** (record npz: eigenvalues of controller.A_of(d, e, f); alpha). Are the stability constraints active: poles at -0.0500, alpha at the cushion -0.0501? Report the active constraints with the value (§6).
6. **n_active is not reliable on lattice records.** It counts the interior local maxima of the stored 2^-6 curve within 2e-3 of the curve's maximum, so a maximum at w = 0 reads 0 (an artefact) and a design with one missed peak reads 1 (a true count at that design, not an optimum's structure; §8, §19). Read the stored gain curve (npz omega_grid, gain). The stage-A edits of 20261010j (uncommitted on 2026-10-14) add an "active" field that includes the end points; n_active itself is unchanged.
7. **The gate lines**: "continuation REJECTS", "certified prefix" and "tau governor: cap". They mark the real refusals (a round lost at the gate), which SUMMARY.txt did not carry before 20261010h (§5, §19).
8. **The stop line** ("PROGRESS STOP" or "DEADLINE STOP") and, for cost, the cumulative "[ledger]" lines (§19, §20).

## 1. Inner solver (SQP) and stopping rules

### Do not repeat

- **Do not call a plateau "converged", a "KKT point" or a "fixed point" until the known stall mechanisms have been ruled out.** [mechanism only]
  Every K+B+C value reported as converged in the 7.6-7.96 range was a stall: ne=200 7.95x, ne=100 7.92x, 7.95721, 7.951836, 7.950855, 7.925385, 7.929388, 7.657552, 7.848591 and 7.824127. The causes were the compensator pair at a double pole on the line, quasi-Newton memory carried across rounds, the tau governor cap, late face-S entry, and rows not following their peaks. The fixed code reached 6.438335 and 6.486505 at ne=200 and about 6.40 at ne=100, roughly 19 % lower. (corrected 2026-10-14: 9.748986, which this list used to include, lies outside the range and had a different cause, the admissibility cushion applied to the exactly computed compensator poles; see §6 Bugs.) [STAGE1 errata l.1-6; STAGE1B errata l.1-6; STAGE2 errata l.1-11; STAGE3 l.1-6; STAGE5 errata l.1-6, §29.6 l.1652-1657; TRACKER l.157, 355, 386, 392, 421, 449, 489, 511-523]
- **Do not carry the quasi-Newton (BFGS) matrix across outer rounds. Carry only the trust radius.** [clean A/B]
  Plateau rounds replayed with H = I: 7.509409 -> 7.090410 in 40 iterations, where the carried run reached only 7.450646. 6.864869 -> 6.806314 in 25 iterations, where the carried run needed about 280 to reach 6.825715. `--sqp-carry-h off` is now the default, and `--sqp-carry` (passed at bfs/run_bfs.sh:103) carries the radius only.
  Current code (checked 2026-10-14, HEAD ad580e3): the help text of `--sqp-carry` (run_case_epi.py:1932-1933) still says "carry the SQP trust radius and BFGS matrix across outer rounds", which is stale. (revised 2026-10-14) [STAGE1 l.5-6; STAGE1B §8 l.388-389; STAGE3 l.5-6; STAGE5 §28 l.1437-1454; TRACKER l.527, 532]
- **Do not bring back the GL tail knobs that were removed after negative tests.** [clean A/B]
  The knobs: merit weight 1, Oren-Luenberger scaling, radius shrink, exact compensator curvature plus cushion, 2-norm trust ball, and a second-order correction on the compensator block. All reached 7.9366-7.9394 from 7.9403; the plain SQP reached 7.9351 in 15 iterations. Removed 2026-09-25: MERIT_CTRL, HMIN_REL_TOL, NU_H, TR_BALL, CTRL_CUSHION, CTRL_HESS, SOC_CTRL, SOC_MAXIT, TR_SHRINK, H_SCALE, MERIT and `--sqp-merit`. A replay was identical before and after (md5 3e5b9dfcc3286a50268b0fcabeb68ece). The BFS correction back onto the compensator line works and is a different mechanism (see the Maratos entry below). [STAGE5 §24 l.1147-1161, §29.5 l.1639-1650; CLEANUP §7; TRACKER l.516]
- **Do not shrink the trust radius to (a multiple of) the accepted step off the face S. This was rejected three times.** [clean A/B] (BFS 20261008c, one pair; the GL readings are mechanism)
  GL §24: the radius collapsed to 2e-6. GL §29.2 (off the face): 7.9056 against 7.9053 for the plain SQP, collapsing to 1e-10 with stale tops. BFS `--sqp-partial-shrink` (radius 2 alpha |d|, 20261008a): every run stalled from round 3-6 on, with codes 6/12 and stat_value 1.1e7 to 1.1e17. In the A/B 20261008c, SISO reached 641.52 without the shrink and 685.28 with it. It has been off by default since 20261008c (enable with SHRINK=1, directories _shr). A one-round sandbox gain from a checkpoint (alpha 1/2, certified 666.04) did not predict the tail. The deliberate exception is GL's double-pole face S: there the 2-norm trust region is shrunk to twice the accepted step (PAIR_BALL, sqp_inner.py:41), with the line search started at alpha = 1, and that is current nominal GL behaviour. The BFS modal compensator has no face S, so the exception does not arise there. (corrected 2026-10-14: the rule had been stated without this scope.) [STAGE5 §24 l.1150, §26 l.1323, §28 l.1490-1495, §29.2 l.1566-1569; CLEANUP §7; BFS.md l.298-302, 648-669, 717]
- **Do not fight overfitting of Omega with a frozen trust ball or a fixed short inner budget. Adapt the budget instead (see Decisions).** [clean A/B] (three arms, one case, equal evaluations)
  Ball 0.05: certified/t 1.63, 1.17, 1.09 and gamma about 10.2 at round 4, against 9.410 for 6 rounds of 20 iterations. 24 rounds of 5 iterations: 9.989 against 9.410. This confirms the frozen `--trust_warm` finding: 20x the calls for no gain. [STAGE3 §7 l.156-169; STAGE1 l.369-373; TRACKER l.61]
- **Do not tune solver tolerances to fix stalls. QP accuracy, mu, opt_tol, level scaling and the line-search fallback were all ruled out.** [clean A/B]
  OSQP ends 60-80 % of steering QPs on its iteration limit, yet a converged OSQP (max_iter 200000: 7.9587 against 7.9579) and DAQP (identical to 12 digits, +30 % calls) change gamma only in the 9th-12th digit. mu never starved: it went 1 -> 0.0064 against a starvation threshold of 1e-4. `--level-norm off` gave the same gamma at 91 calls against 75. opt_tol 1e-6 gave 9.6618 (certified 12.3 against t 9.1) and 1e-4 gave 9.2525, against 8.9997 at 1e-10. `--ls-fallback` took 191 calls against 75 for an identical gamma. The reading "tight opt_tol is early stopping that regularises" was really the working-set defect. [STAGE0 §17.5 l.1037-1055; STAGE1 §7 l.174-207, errata l.14-18; STAGE1B §4-5 l.227-279; TRACKER l.71, 93]
- **Do not blame code-6 stops on the oracle's noise floor before checking what the diagnostic measures.** [mechanism only] (ambiguous)
  STAGE1 §11/12.3 read every ne=200 code 6 as a real Wolfe failure at the noise floor, with balance residuals of 1e3-1e4. STAGE1B §3-4 and STAGE5 §25-28 later showed that residual was one branch at a non-active peak, and that the stalls came from the kink, the double pole, stale memory and the wrong abscissa gradient. TRACKER l.94 still states the noise-floor reading. At ne=100, code 6 came from the unsatisfiable |Im| cap. [STAGE1 l.176-202, 328; STAGE1B l.81-130, 227-265; TRACKER l.94]
- **Do not add another inner solver or solver class: IPOPT, a bundle method, gradient sampling, QPALM, qpOASES or a Newton polish.** [mechanism only]
  The stalls came from constraint degeneracy and stale memory, not from a limit of the solver class, and the inner solve is not the bottleneck. IPOPT and qpOASES cannot be installed with pip; QPALM installs but was never measured. An unsafeguarded Newton/LM polish over 7 active peaks let an unlisted peak rise to 10.119 at w = -1.435 and pushed a compensator pole off the margin (-0.0492). [STAGE1B §7.2 l.258-259, 359-361; STAGE2 §3.4 l.284-303; STAGE5 §30.10 l.1847-1849; TRACKER l.62, 79, 160, 163, 165; STATUS 0b, 78-79]
- **Do not use pyGRANSO for new runs. It is kept only for the frozen path.** [clean A/B] (STAGE5 §8: four arms, identical start)
  "pyGRANSO beats the SQP as the exchange's partner" (STAGE1B §7.2: 9.375 against 9.684) and "ties at equal evaluations" (§8.1) were artefacts of the working set and of the compensator line. On the corrected loop the SQP reaches 7.950855 (KKT 2.0e-4) against pyGRANSO's 7.961104 (3.4e-2), both at about 150 LU per round; pyGRANSO cannot represent the double pole. `--pyg-bandmax` (one band-max row) was the only way to give pyGRANSO in-solve refinement. A hand-set analytic gradient is ignored by pyGRANSO, which then reports "converged" at iteration 0; gradients must go through a torch autograd Function. [STAGE1B §7.2, §8.1, §8.3 l.335-476; STAGE2 l.49-53; STAGE5 §8 l.463-490, §30.10 l.1850; TRACKER l.79, 108, 271-276, 302, 421-434]
- **Do not form sigma_2 blocks inside the solve.** [mechanism only] A faithful replay formed zero blocks, because the per-round enrolment already covered w in [-0.53, -0.50]. Removed. [STAGE5 §29.2 l.1562-1566; CLEANUP §7; TRACKER l.549]
- **Do not use constraint generation for the epigraph QP, qdldl as the Clarabel KKT solver, or a looser gap tolerance.** [clean A/B] (the same QPs, one switch each)
  Constraint generation ended with about 1500 of the 2716 rows and took 10-12 s cold against 2.2-2.7 s. qdldl was 45 % slower than auto (which is faer). The solve stops on AlmostSolved at a gap of about 1e-7 either way. `--qp-linsolve` was removed. [STAGE6 §6.26 l.850-857; CLEANUP §12; TRACKER l.652]
- **Do not pursue a second QP per SQP iteration (BFGS multipliers taken from the old QP).** [mechanism only] It saves about 12 % of a round at ne=100, its size does not grow with n, and it is an algorithm change. TRACKER l.652 still says "to A/B", which is stale. [STAGE6 §6.26 l.838-840, §6.28 l.1043-1045; TRACKER l.667]
- **Do not rescale QP rows or relax Clarabel tolerances to cure QP failures. Find the offending block on a dumped QP.** [single pair] (one dumped QP)
  qp_fail_1.npz (decentral strip, 20261010e): sigma-row gradients range from 1.2e-5 to 3.7e3 and right-hand sides from 5e-12 to 521. Without the LMI cones it solves in 28 iterations (26 with rows divided by t, 28 with unit rows: the Ruiz equilibration already does the scaling). With the LMI cones it gives NumericalError at 1e-10, 1e-8 and 1e-6, and InsufficientProgress with regularisation. The ladder below is not a cure: the replayed LMI QP failed at all three tolerances.
  Current code (corrected 2026-10-14; re-checked at HEAD ad580e3, revised 2026-10-14): the rule is contradicted by a tolerance ladder kept as a fallback on the lattice path only. In `subproblem(..., relax=)`, a QP that is not Solved at 1e-10 is solved again at 1e-8, then at 1e-6, with max_iter 400 (added in 20261010f; sqp_inner.py:1046-1057, `relax=lattice is not None` at l.1233, 1240, 1648). A retry that succeeds resets the status string, so it leaves no trace in the round log. No 20261010g log shows a non-Solved status, so whether the ladder still fires after the LMI fix is unknown. Keep it with a stated reason, or remove it with a CLEANUP entry (§17). [BFS.md l.778, 783-784; sqp_inner.py:1046-1057]
- **Do not halve trials that cross the closed loop's line (`--lattice-cross cut`). Weigh them by the merit and admit only admissible iterates.** [confounded]
  Evidence: a mechanism plus confounded runs; a CROSS=cut A/B was never run (corrected 2026-10-14). In 20261010c all six runs stopped on the progress rule after 5-10 rounds, with 26-128 cut trials per round: SISO 641.71, central 697.64, decentral 560.19; without the strip 873.10, 679.76, 552.10. Those stalls had three causes, found together: rows aimed exactly at the admissibility line (fixed by LAT_CUSHION), the cut rule, and "the deepest", the compensator rows dropping the real pole at -0.05 (fixed by `_cluster_idx`). All three changed at once in 20261010d, so these values do not measure the cut rule. The mechanism stands: central trials crossed 0.13-0.15 past the line (up to 0.23), and halving cannot undo a coalescing pair, whose motion goes like sqrt(step). `--lattice-cross merit` is used since 20261010d; CROSS=cut is kept only to reproduce old runs. [BFS.md l.286-287, 741-746]
- **Do not generalise reproducibility from a stressed budget.** [mechanism only] (superseded: STAGE0 §15.1) Three runs giving 10.259071 / 10.355313 / 10.263187 came from `--wall 40 --outer 3`, which made per_outer negative and left the inner solve on its 10 s floor. At production settings the clock runs were bit-identical. [STAGE0 §2 l.62-97, §8 l.254-261, §15.1 l.616-619]

### Bugs (symptom -> cause -> fix)

- **Select the inner solve's returned iterate with exactly the gate's acceptance test (`--select-cons on`): no stricter, no looser, and including the certificate's verdict.**
  Symptom: every stalled child had found a better design and had it refused (KSP+B 9.917, KSP+C 9.687, KSP+B+C 8.910; at ne=200, 9.620), and the gate's rejection loop wasted 792 of 2710 calls (29 %). Cause: the returned "best" was chosen on closed-loop feasibility alone, although both compensator constraints were already in the inner problem; STAGE0's proposal to "move the constraint inside" was a wrong diagnosis. A first fix tested al_ctrl <= -eps, stricter than the gate, and gave 9.367 against the frozen 9.046. Once aligned with the gate, K+B+C reproduces 9.984257. Admissibility now also requires `bool(_clr)` (run_case_epi.py:656). [STAGE0 §15.4 l.727-740; STAGE1 §2 l.52-89, l.264-289]
- **Record every inner solve's termination code and statistics, and look the codes up in that solver's source.**
  pyGRANSO's solution object used to be discarded, so the frozen records have no codes (collect.py's stall label is a guess). pyGRANSO codes: 4 = maxit; 6 = Wolfe bracket failure at a feasible point (misread as maxit in STAGE0 §15/§17.4); 12 = steering-QP failure that skips the fallback ladder (UnboundLocalError 'y', qpSteeringStrategy.py:250 / bfgssqp.py:330; never patched, not seen at eps 0.05). SQP codes: 0 = stationary, 4 = budget, 6 = trust-radius collapse, 12 = QP failed even after a Hessian reset. [STAGE0 §1 l.55-60, §14 l.519-575, §17.4-17.5 l.997-1035; STAGE1 l.176-179, 210; BFS.md l.648-652]
- **SQP stationarity must require a small predicted decrease, not only a small relative gradient (`--sqp-stat pred`).**
  Symptom: from round 4 on, at_dec exited after 1-3 iterations with one active row of gradient norm 1.4e3-1.7e6 (the atom amplitudes) against stat 0.009-0.16. In SISO at ne=100, rounds 0-6 ran 4-8 evaluations each; with the fix they ran 33-122. Fix: stationarity also requires a predicted decrease <= 1e-7 t. The default auto means pred for MIMO and rel for SISO. Earlier, the test was scaled by the largest row gradient (7e3 at ne=200) and fired after one iteration; it now uses the mean active row gradient. [STAGE2 l.353-355; STAGE6 §6.10 l.251-268, §6.14 l.361-378; TRACKER l.624, 634-635]
- **Never modify the solver's step after it returns. Put step limits inside the subproblem.**
  Symptom: the tau governor clipped the SQP step after the solve (0.0629 -> 0.0117), so the certified design was a point the SQP never evaluated, with a peak (8.231 at +1.788) present at neither endpoint. Fix: a displacement cone ||z - z0|| <= rho in every subproblem. [STAGE5 §22 l.1012-1024; TRACKER l.506]
- **Step governors must not react to successful events (`--tau-split ignore`).** The governor capped the next step after successful homotopy splits, so rounds 10-16 ended on code 6 with caps of 0.0021 -> 0.034. v5 with the fix: 6.410212 after 31 rounds and 1,651 s, against v4's 6.4164 after 57 min. [STAGE5 §29.1 l.1525-1532; TRACKER l.546]
- **Floor and log any solver state carried across rounds, and discard it after a failed or collapsed solve.** A collapsed radius (7.8e-5) carried into the next round caused a 3-round stall; the carried radius is now floored at 0.1 x the fresh radius. A solve that ends on code 6 or with failed subproblems now passes no H and no radius on: one ne=100 run sat at 7.770563 for four rounds, and the same design with H = I reached 7.665533 in 25 iterations. (superseded in part: `--sqp-carry-h off`.) [STAGE5 §5.3.1 l.325-328, §23 l.1081-1087, §26 l.1366-1369; TRACKER l.511]
- **Compare like with like in acceptance tests, and refresh reference levels every round.** The "never worse than the start" guard compared reduced-model iterates with the loop's certified t0, so at tiny steps every iterate looked worse and nothing was returned; it now compares with the SQP's own start value on its own model. The SQP's t0 was the run's start value, so a stationary SQP reported 7.964064 at a design certified 7.951836; it is now the current certified best. [STAGE2 l.106-109; STAGE5 §5.3.1 l.329-332, §11 l.557-559; TRACKER l.396-400]
- **Progress tests need a threshold of at least the certificate tolerance.** `--converge` never fired because the SQP improves by 1e-9 per round at a fixed point. [STAGE5 §24 l.1222-1224; TRACKER l.521]
- **With budgeted inner solves, "certificate agrees with t" is not convergence. Inner stationarity is required as well.** [STAGE1B §8.2 l.438-440; TRACKER l.134]
- **Penalties must be scale-free (`--sqp-pen adaptive`). Never carry absolute constants over from GL.**
  GL's nu = 100 is about 10 x sigma on GL but 0.13 x sigma on the BFS. A step moved a compensator pole 0.024 across the line for a penalty of 2.4 against a sigma gain of 12 (752.96 -> 740.74), and every round returned its start (jobs 760989, 761011, 761012). Every BFS run before 2026-10-04 used this penalty, including the 769.57 result. The adaptive penalty steers by x10 up to 6 times, keeps nu >= 1.5 x the largest stability multiplier, starts at 100 and never decreases within a solve. Merit penalties also need a deadband equal to the admissibility margin: the start's own 5e-5 excursion had been penalised. [STAGE1B §7 l.313-314; BFS.md l.279-283, 562-568]
- **Pair an exact penalty on a curved constraint with a second-order correction (Maratos effect).** With the adaptive penalty alone, nu went from 100 to 1e5-1e7, steps were cut to alpha about 1e-3, and 752.96 -> 743.07 took 10 iterations. With a least-norm Newton step back onto the compensator line: 752.96 -> 732.09 -> 702.07 at alpha 1 to 1/8. With the modal compensator the correction is a Newton step on the violated block rows. [BFS.md l.284, 577-578]
- **Bound the number of inadmissible iterates in a merit-based solve (LAT_BACK = 3).** In 20261010d SISO, round 7 accepted a crossing (6e-4 past the line), and 247 of the 251 evaluations in rounds 8-10 were not clear. The solve now returns to the last admissible iterate after 3 iterations outside, with a quarter of the radius. [BFS.md l.762]
- **Never let two memories of the same cut compound.** On face S the radius shrink and the warm alpha (twice the last) ratcheted each other down to a radius of 2.5e-7. On the face the line search now starts at alpha = 1. Replay: 7.9285 -> 7.8677 in 40 iterations. [STAGE5 §28 l.1490-1495]
- **When every SQP step is rejected, first print each row's linear prediction against the true value along the ray** (`--sqp-debug-ls`, DEBUG_LS). The first SQP had a sign slip in its cone rows: the block predicted dt = -0.30 where sigma_1 allowed -0.07. [STAGE1B §7 l.310-313; STAGE5 §29.2 l.1534-1538]

### Decisions

- **The SQP is the inner solver. Pass `--inner sqp --sqp-carry --sqp-trust 0.01` explicitly, because the code default is still pygranso.**
  sqp_inner.py solves a Clarabel QP with cones, and a damped BFGS on the Lagrangian is fed by the cone duals. Every step is certified optimal, at about 2 oracle evaluations per iteration against pyGRANSO's 5-10. It was chosen for structural correctness (the Clarke block and all near-line eigenvalues) at equal cost. Health metric: evaluations per iteration; 2-3 early and 5-8 late signals line-search trouble. [STAGE1B §7 l.289-295, §8.1 l.407-422, §8.3; STAGE5 §30.10; BFS.md l.630]
- **Represent repeated singular values by the full 2x2 Clarke block (an SOC, `--sqp-block on`), never by two scalar rows.** pyGRANSO's steering QP sees only the diagonal Y. Finite differences at the K+B+C kink: FD 4.58484, block 4.58530, single branch 4.57156. [STAGE1B §3.1 l.211-225, §7 l.296-299; TRACKER l.74, 91, 108]
- **Make every stability row elastic (Fletcher S-l1-QP),** so that a start outside a line is walked back in instead of making the subproblem PrimalInfeasible (the K+B start had its compensator at -0.034). [STAGE1B §8 l.378-387; BFS.md l.280]
- **Use an iteration budget (`--inner-budget iters`) with the adaptive inner budget (`--inner-maxit-adapt`).**
  Under a clock budget, rerun identity depended on machine load; under an iteration budget the reruns are bit-identical. The adaptive budget doubles if certified/t <= 1.05, halves if it exceeds 1.15, and stays within [5, 40]: K+B+C 9.279 against 9.410 at about 250 evaluations, KSP+B+C 9.449 against 9.607. Nominal: `--inner-maxit 10 --inner-maxit-adapt` (bfs/run_bfs.sh:100). A fixed maxit of 100 from poor starts caused 4 on-the-line refusals and 1 continuation refusal and stuck at 9.674, while maxit 25 gave 0 refusals and 8.958: the short clock-budget solves had been the implicit step control. [STAGE0 §8 l.203-252; STAGE1 §12.1-12.3 l.369-387; STAGE3 §7 l.169-189; STAGE5 §30.10 l.1854; TRACKER l.57, 61]
- **Warm-start the line search at twice the last accepted alpha (ALPHA_WARM), except on a manifold face and when the radius is being shrunk.** Evaluations per iteration went from 6-7 to about 2; rounds went from 150-300 evaluations to 60-90. [STAGE5 §26 l.1336-1340; TRACKER l.526, 535]
- **For a solver failure, prefer the fix that changes only the failing steps** (for example, step up the fallback level rather than ridge every Hessian), and measure it against the recorded failure counts. [STAGE0 §14.4 l.571-589]
- **Run Clarabel on one thread (max_threads = 1).** The default (all cores) was 28 % slower (median 2.44 s against 1.76 s) and gave a bitwise-identical solution. [STAGE6 §6.26 l.846-849; sqp_inner.py:1043; CLEANUP §12]
- **Keep row screening (`--row-screen 0.05`) only together with in-solve refinement.** Rows below 95 % of the maximum get a zero gradient; an evaluation takes 1.90 s against 2.15 s. An A/B with screening off showed the same gaps, so screening was not their cause.
  Current code (checked 2026-10-14 at HEAD ad580e3; revised 2026-10-14): bfs/run_bfs.sh:103 passes `--row-screen 0.05`, but screening is inert on the BFS lattice path. With the lattice oracle the rows come from lattice.evaluate, which computes every row with its gradient (sqp_inner.py:396-404), and the screening branch (l.484, `self.row_screen > 0 and self.oracle is not None`) needs the reduced oracle. The flag works only on the GL reduced path (tools/n100_kbc.sh:12 and the other GL scripts). On the lattice a value costs as much as a row, so the trick would save nothing there (an/omega-growth.md P7). Refactor candidate, §17. [STAGE5 §13.1 l.637-641, §18-19 l.892-906; sqp_inner.py:396-404, 484]
- **tau0 (note item 11) is gone. Delete function defaults that the CLI always overrides.** Both values are now 1.0. The `--tau0` flag still exists and is a refactor candidate. [STAGE1B §5 l.267-272; TRACKER l.82]

### Decisions

- **Keep in-solve refinement on (`--sqp-refine 1e-4`), with the tolerance at the scale of the per-round gains, not of the level.**

## 3. Peak following

### Do not repeat

- **Do not locate peaks by golden section or by a pre-scan. Use safeguarded Newton on the exact slope, with bounded halving and secant curvature.** [clean A/B]
  Golden section needed 11-16 evaluations per peak, with accuracy limited by the window, and the frozen code already had a better Newton (ClosedLoopResolvent.peak). The Newton finds tops exactly (checked against a 4001-point scan) in 7-15 calls cold and 1-2 iterations warm. A 20-halving safeguard cost 80 calls on a flat top. The 21-point window pre-scan, added for an unconfirmed twin-peak hypothesis, took 2.6 s of a 4.6 s evaluation; with `--follow-scan 0` the rows were identical (2e-14), the path was identical, and an evaluation took 2.2 s. [STAGE5 §16 l.801-813, §17 l.854-868, §24 l.1165-1180; TRACKER l.322, 491, 495, 517]
- **Do not round a followed row's frequency to a grid.** [mechanism only] Lattice bracket-and-refine (2026-10-06 to 10-08) left the row 1.2e-7 to 9.6e-7 x sigma below the top, giving merit noise of about 5e-4 at sigma about 470. With exact Newton the certified value is 1446.392650, equal to smax. The parallel Hermite-jump refinement (3.85 waves cold against 10.6) is superseded too. [BFS.md l.173, 612, 683, 702, 713]

### Bugs (symptom -> cause -> fix)

- **Every row type tied to a peak must go through the following code.** sigma_2 block rows stayed at fixed frequencies: the round was refused at 7.965, while with following it was accepted at t = certified = 7.955734. [STAGE5 §11 l.552-555; TRACKER l.370-381]
- **Check for shared tops at every evaluation and restart duplicates from their own bases (FOLLOW_DEDUP). Merge members closer than 1e-3 after following.**
  Members based at -0.5280, -0.5105 and -0.5094 all sat on the top at -0.524950 (7.9057032), while the neighbouring top at -0.509496 stood at 7.9063061. smax was understated, the radius went to 1e-10 and the solve ended on code 6. Cost of the fix: +8 % wall time.
  Current code (checked 2026-10-14, HEAD ad580e3; revised 2026-10-14): the rule does not hold on the BFS lattice path. The FOLLOW_DEDUP block (sqp_inner.py:532) needs the reduced oracle (`self.oracle is not None`), and lattice.evaluate (lattice.py:755-850) has no shared-top check. Only the round-end merge of members within 1e-3 is active, and it misses members locked on one top: a member whose top lies within 1e-3 of another member is not moved, so it is never merged (run_case_epi.py:3884-3885). This is one of the three safeguards the lattice path lost (§19). Without it, round 12 of 770632 would carry three followed members on the one top at 4.1806, and in 770633 up to about half of the followed members may be duplicates (inferred from the counters, §19). The uncommitted stage-A edits pass FOLLOW_DEDUP to lattice.evaluate. [STAGE5 §29.2 l.1553-1561; TRACKER l.382-383, 548; sqp_inner.py:532; an/missed-peaks.md P4; an/eval-waves.md VERIFIER missed (1)]
- **Key warm-start caches coarsely and bound them.** The cache was keyed at 1e-8, scanned linearly and grew on every search; it is now keyed at 1e-3 with direct neighbour lookup. [STAGE5 §16 l.817-819]

### Decisions

- **On the lattice, follow with lattice._newton at exact frequencies, one member per rank.** A step and its two halvings are evaluated side by side; the stop is |sigma'| <= 1e-7 x sigma (`--lattice-tol`); exact points go in a side cache of XCAP = 2, never in the lattice cache. The tops match the serial Newton to 2e-14. Cold, 4 members took 6 waves; the same design again took 1 wave. A side cache of 4 ran the sandbox out of memory.
  Current code (checked 2026-10-14, HEAD ad580e3; revised 2026-10-14): lattice._newton searches only the member's BASE +- `--follow-radius` 0.1 (lattice.py:547) and clips steps to FOLLOW_TRUST 0.05. A candidate outside that window is dropped, and Newton stops where it is. Nothing re-centres the window when the top drifts past its edge; the reduced path searched the full window in that case (STAGE5 §13.1). In 770632 round 11 a row stopped on such an edge 5.3 % below its top (§19). The uncommitted stage-A edits re-centre the window at the edge (FOLLOW_EXTEND = 2 per evaluation). [BFS.md l.167-172, 698, 702; lattice.py:547; an/missed-peaks.md P3]
- **The only finite difference in the loop is d2 sigma / dw2, used when no secant value is carried (5.7 % of a big round).** An analytic second derivative is not worth it. [STAGE6 §6.26 l.800-808; TRACKER l.653]

### Measured facts

- **Newton converges to the nearest local maximum. Only a level-set search finds a narrow neighbour.** Twin peaks 0.0055 apart: 8.6156 at -1.3625 against 9.540 at -1.3570. [STAGE5 §19 l.912-915]

- **Report stability as the winding count at save. `--rect_cert` is a legacy name for the layered line gate, not a rectangle cover.** [STAGE5 §18 l.872-883]

### Do not repeat

- **Do not reinstate a cap on the compensator poles' |Im|. Keep compensator stability as a requirement and take the band from the closed loop (`--ctrl-imcap off`).** [mechanism only] Arm S (selection fix, cap kept) gave t = inf at outer round 1 with 510 calls a round, and the cap was what broke the line search (code 6 at ne=100). User decision 2026-09-16. [STAGE1 l.74-80, 105-108; TRACKER l.78]
- **The "cost of compensator stability" (4.2 % or 4.4 %) was an artefact of the 20-iteration budget.** [clean A/B] (budget-matched, one case). At maxit 100, keeping stability gave 8.9997 (904 calls) against 9.0587 (1130 calls) when dropping it; on K+B+C over 8 rounds, dropping it was 3 % worse. `--ctrl-stab off` is only a measurement switch. (ambiguous: the text gives 4.2 % in §4.1 and 4.4 % in §4.2 for the same withdrawn number.) [STAGE1 §4 l.75-76, 125-149]
- **Never use the compensator Lyapunov LMI (`--sqp-lmi`), and above all not together with `--ctrl-modal`.** [single pair] (BFS: one dumped QP with and without the LMI cones); [mechanism only] (GL)
  GL: the LMI fails at near-double poles (cond P about 1e7, Clarabel NumericalError), and without a box on dP the step moved the pole outward. BFS 20261010e: `--sqp-lmi` defaults to on (run_case_epi.py:1936, checked 2026-10-14), and sqp_inner built the LMI whenever there was no Hermite block and no face pair, that is, always with the modal compensator, and it replaced the modal rows. The 20261010g runs then had no code 12, and decentral strip moved at once (§20). BFS.md l.296's "stays off" described the intended default, not the effective one.
  Current code (checked 2026-10-14, HEAD ad580e3; revised 2026-10-14): `--sqp-lmi` still defaults to on (run_case_epi.py:1936; its help text says "never with --ctrl-modal"). sqp_inner skips the LMI for the modal compensator (`and not getattr(pk, 'modal', None)`, l.785-786). - **Do not apply polynomial stability criteria to the whole compensator.** [mechanism only] The degree-16 Hermite matrix has lambda_min/tr about 1e-17. Use 2x2 blocks only. [STAGE2 §3.2 l.220-224; TRACKER l.181-191]
- **Do not linearly penalise a measure that is quadratic in the violation (MERIT_CTRL = 'hermite'), and do not add cushions the merit cannot reward.** [mechanism only] The iterates wandered to -0.0409 / -0.0591, 0.009 past the line, at a Hermite violation of only 1.6e-7. [STAGE5 §25 l.1248-1261; CLEANUP §7; TRACKER l.523-524]
- **Where poles may coalesce, do not constrain stability by per-pole rows, a single max-Re row, (tr, det) of eigenvalues extracted from a general A_c, or 2x2/3x3 Hermite blocks on a general A_c. Use coordinates that are smooth there.** [mechanism only]
  The max-Re row is not Lipschitz at the double pole (pyGRANSO advanced in crumbs at -0.0500 / -0.05001). Per-pole rows break because the poles split like sqrt(step). det's gradient vanishes at an exact coalescence optimum, a constraint-qualification failure. On the BFS tridiagonal compensator, a triple pole sat at -0.05: a perturbation of 1e-6 moved the poles by 0.015-0.035 (cube root); the rows predicted -0.05000012, the step gave +0.0902, and all 8 halvings were cut. - **Leave an identified face only at a point that is stationary on it, with a multiplier sign that says leaving pays.** [clean A/B] (one case). Releasing on the first QP that allowed it gave 7.901729 in 62 evaluations, against 7.878932 in 27 when held. [STAGE5 §26 l.1358-1360]

- **One compensator line for every component: `--ctrl-line eps`, i.e. Re <= -eps for the gate, admissibility, both inner solvers and the stabilisation phase. [STAGE1B §8 l.383-387; STAGE2 l.88-92; TRACKER l.139-145]

No Hermite block, no face S, no LMI.** Jacobians agree with FD to 7.6e-11. ### Measured facts

- **Optimisers park compensator poles on the margin. A double pole on the line is a constraint-qualification failure, not a tuning problem.**

## 7. Reduced (projected) oracle

The reduced oracle is the GL nominal oracle. It is not the BFS production path: the BFS has used the lattice full model since 2026-10-06, by the user's decision to "drop the reduced model, parallelise the full one".

Current code (checked 2026-10-14, HEAD ad580e3; revised 2026-10-14): the BFS scripts still default to the reduced oracle. bfs/run_bfs.sh:70 and 87 use `${ORACLE:-reduced}`, and testplant.slurm:80-86 and codesign.slurm:90-96 export `ORACLE=${ORACLE:-reduced}`. Every lattice run must pass ORACLE=lattice, and the `_lat` directory suffix depends on it. Refactor candidate, §17.

### Do not repeat

- **Do not go back to a reduced inner model for the BFS without a fundamentally different, stability-preserving reduction.** [mechanism only]
  A model built at the central record (dimension 480) erred by 3.6e-3 for port moves of 0.1 (where the full peak at w = 0 grew 15x), 3.9e-2 for moves of 0.3, and 22 % for moves of 0.8 plus a 30 % controller change. Near the plateau 13 of 44 rounds were refused. Port-range input bases do not compress: rank 56 / 87 / 117 / 169 for the actuator at 1e-2 to 1e-6, i.e. 1000-3000 vectors in all. A dimension-1186 model had a spurious near-axis pole (sigma 3e7 at w = 3). The driver's dense work grows like dim^3: missed_peaks on a 982x982 Hamiltonian took 44 s per call, the dense eig of the 491x491 pencil 6 s. Spurious Ritz values at +0.03 to +0.11 passed the 1e-3 residual filter (true pairs have 1e-10 to 1e-15), so the filter is 1e-5 on the BFS. A hybrid scheme was proposed and never built. - **Do not take near-line eigenpairs from shift-invert Arnoldi with left vectors matched by nearest eigenvalue.** [mechanism only] The gradients were wrong and Clarabel returned NumericalError; after the inverse-iteration fix the path still gave 8 rows against 7 and a gradient off by a factor of order one. ## 8. Lattice oracle (BFS full-model inner loop)

### Do not repeat

- **Do not refine the strip quadtree beyond two levels, do not enlarge STRIP_RHO beyond 2^-6, and keep k = 1 per strip shift.** [clean A/B] Pre-refining by 3-5 levels placed 1.1-8x more shifts, and a 2^-5 ball left eigenvalues within 0.011 of each other unexhibited. Per strip shift, k = 1 / 2 / 4 / 6 took 2.35 / 11.0 / 9.9 / 10.2 s, i.e. 583 against 1340 shift-seconds for k = 1 against k = 4. A greedy smallest kept set changed little (200-250 disks for a depth of 0.25). [BFS.md l.177-182, 700-701]
- **Keep k = 1 on the line.** [clean A/B] (cost, one record, serial). k = 2 gave 10 rows instead of 8 at 3.2x the line cost (439 s against 139 s); k = 3 costs 2-4x. The missing rows come from the strip. (revised 2026-10-14) This rule is about cost and rows, not proof. The k = 1 line cannot see an eigenvalue right of the line hidden behind one at the same Im, so the line's alpha taken alone is not rigorous (§19). `LATTICE_K=2` was built in 20261008e and, by BFS.md and STATUS.md, never run on the cluster. [BFS.md l.175, 614, 678-679; an/gate-refusal.md G5 and VERIFIER]
- **Do not use a nearby cached factor as a preconditioner on the test plant.** [mechanism only] GMRES needs 3-12 iterations depending on dw; a factorisation costs 0.5 s, about 32 solves, while a sigma_1 evaluation needs 18-34 solves, so reuse is no cheaper. This was not measured on the full mesh. [BFS.md l.703-706]
- **Do not try to cache 2n-pencil factors across levels, or to put the winding march on the lattice.** [mechanism only] The pencil carries M / gamma^2 in a full-rank block, and a count takes 3400 samples, more than any cache, twice per run. [BFS.md l.192]
- **More factor reuse will not speed up the line: a line centre's cost is Arnoldi** [mechanism only] (25-85 applications, 0.6-1.9 s, on top of a 1 s factor; warm starts do not help, 37-154 applications). A kept cover on a design moved by 1e-4 needed 22 of 24 shifts in one wave. [BFS.md l.193, 613-614]

### Bugs (symptom -> cause -> fix)

- **Never break scheduling ties by rank index.** Ties went to the lowest rank, so every new point of a small wave landed on the driver and the first ranks: 5816 driver factorisations in central against 358 in SISO. Ties now go to the least-loaded rank, then the one with fewest factors, then a rotating order: 118-129 driver factorisations. [BFS.md l.165, 628, 637]
- **Give the QP a row for every eigenvalue that can cross within a step, not only those nearest the line's centres (hence the strip).** With line-only rows, -0.1444 +- 0.0446i hid behind -0.0723 +- 0.0140i, the line was not clear in 62-77 of 141-144 evaluations, and the cold central run stalled at 472.22. The strip [-eps - 0.25, -eps] x [0, band] fixed this in 20261009b. [BFS.md l.176, 677-682]
- **Audit the end-of-run and post-processing paths whenever the oracle is swapped.** The lattice run's gain curve was computed serially on the full model (about 1700 factorisations, 37 min on the test plant, hours on the full mesh); it now runs on the ranks at the points of 2^-6. [BFS.md l.622]
- **Overlap the level set with the accepted iterate's strip waves.** A compensator-restored trial ran its level set alone: 903 s of a 2300 s round (fixed in 20261010d). [BFS.md l.189, 740]

### Decisions

- **Shifts sit on a dyadic lattice w = k 2^-l, and the ports and controller enter by Woodbury,** so the plant factors (which do not depend on the design) serve every later design at the same shift, and refining never discards a factor. Put any new full-model shift on the lattice, or in the side cache if it is an exact point. [BFS.md l.163-164]
- **Waves: all outstanding requests of one evaluation go out together, one batch per rank, and the driver computes its own share** (`--lattice-driver on`): 7.7 s per SQP evaluation, against 8.3 s for the rows alone plus 6-7 s for the line before. [BFS.md l.166, 633]
- **The strip is built only for iterates whose rows the QP reads** (the start and the accepted steps). Line-search trials use only the line certificate. [BFS.md l.180]
- **Memory: --mem = ranks x (1 + LATTICE_CAP x factor size).** Test plant: 133 MB per factor; 96 ranks at cap 24 need 450 GB (use LATTICE_CAP=8 on 192 GB nodes). Full mesh: about 1.05 GB per factor plus 3.9 GB per 2n factor, about 25 GB per rank at cap 16, so about 20 ranks per 512 GB node. [BFS.md l.165, 194, 430]

### Measured facts

- **The strip removed the cuts caused by hidden eigenvalues, at twice the evaluation cost.** 20261009b: no incomplete cover, 37-64 stability rows, and from round 3 on 0 cut trials from an eigenvalue without a row. An evaluation took 11-12 s against 5-7 s, with 560-800 shifts per accepted iterate. The stall remained, because the eigenvalues move non-linearly over a step. [BFS.md l.692-693]
- **Read the lattice cost from the cumulative [ledger] lines by kind (eval, level, line, sweep, pool) and their ranks-busy %, not from wall time alone.**
  The 20261010g ledger, by job and kind, is in §20. What it shows is in §19: the level set is the largest single cost in the no-strip runs and rides inside the evaluation waves in the strip runs, every wave lasts as long as its slowest task, and the driver's own serial work is negligible. (revised 2026-10-14: the per-job figures moved to §20.) [logs_in/6logs ledger lines as cited in §20; an/level-set-waves.md; an/eval-waves.md; an/driver-serial.md]
- **On lattice records, n_active is a grid statistic and can read 0: treat it as absent and read the stored gain curve.**
  With the lattice oracle the record's n_active counts the interior local maxima of the stored 2^-6 curve that lie within 2e-3 of the curve's maximum (run_case_epi.py:4995-5000, 5032-5036).   Current code (checked 2026-10-14, HEAD ad580e3): unchanged. ## 9. Linear algebra and MUMPS

### Do not repeat

- **Do not use MKL PARDISO, or any solver with perturbed pivots, on the saddle-point pencil. Use MUMPS** [mechanism only] (METIS via ICNTL(7), ICNTL(14) at 50 %; BFS_MUMPS_ORDERING, BFS_MUMPS_MEM). PARDISO was accurate only to 1e-8-1e-9, and its perturbed pivots moved the computed eigenvalues. [BFS.md l.126-137]
- **Never factor or invert the BFS velocity mass, which is singular (massops.FORBIDDEN = True). Use M only through mat-vecs and R (M = R^T R).** [mechanism only] GL had already moved to M products only, with no dense M, no Cholesky and no square root in the H-infinity path: fit_atoms became better (0.155 against 0.181) and 90x faster, laplace_basis agrees to 2e-12, the tail constants to 1e-15. The H^2 field row uses M^-1 and would need an M-free form on the BFS. [STAGE5 §34.2 l.2322-2353; CLEANUP §9; TRACKER l.605; BFS.md l.18, 118-123, 197-210]
- **Do not rely on MUMPS inertia in complex mode. Use qdldl on the real embedding** [mechanism only] for the numerical range on ker B: equal to dense to 1e-7, 3 s per test at n = 191,720. [BFS.md l.223-229]

### Bugs (symptom -> cause -> fix)

- **Give every ARPACK, Lanczos and svds call a fixed start vector and fix the eigenvector sign.** laplace_basis called eigsh without v0, so two at_dec runs differed from round 0 (t 3.602146 against 3.601816). With the fix, replicas agree to the last digit (3.589316032515165). [STAGE5 §34.2 l.2335-2337; STAGE6 §6.8 l.188-201; CLEANUP §10; TRACKER l.622]
- **Guard every iterative eigensolver call with a logged fallback.** An ARPACK non-convergence ended a run. [STAGE5 §13.1 l.650-651]
- **Move shifts off known poles.** A static gain leaves A_c's poles decoupled in the closed loop, and three solves hit them exactly ("Singular matrix"). Shifts are now moved by 1e-7 / 1e-10 relative. This matters for the BFS zero-controller start too. [STAGE6 §6.31 l.1432-1437; CLEANUP §16; TRACKER l.700]
- **Factor each matrix once, lazily or at warm-up, and cache plant-only quantities per mesh.** The mass LU was refactorised 5x a round and 20x per plant_heights; s_far was recomputed 17x; a pencil built an M LU it never used; the Sobolev LU was eager and was inherited by every worker; the plant's extreme eigenvalues were recomputed at every abscissa certificate. All fixed, bit-identically. [STAGE5 §30.3 l.1710-1712; STAGE6 §6.28-6.29 l.976-985, 1063-1075; CLEANUP §13; TRACKER l.566, 663, 674]
- **Gate every dense n x n operation on n, including paths that only wake up when certain files exist.** warmstart.py:57 did a dense plant eig (160 GB at n = 1e5); it was dormant only because no matching results files existed. It is now skipped for MIMO. [STAGE6 §6.28 l.971-975; CLEANUP §13; TRACKER l.662]

### Decisions

[STAGE6 §6.28-6.29 l.1001-1004, 1104-1112; CLEANUP §14; TRACKER l.677]

- **Instrument by interception (lu_counter's counting proxy for splu), attribute counts by call site, and never edit the pipeline to instrument it.** [STAGE0 §1 l.16-25; STAGE6 §6.25, §6.30]
- **GAIN_NCV = 8 for the BFS** (7-16 applications against 21; sigma agrees to 1e-11). [BFS.md l.124]
- **One assembly path: DOLFINx with the user's nsforms.py.** A scikit-fem fork agreed to 5e-16 (A) and 3e-15 (M) and was removed. Validate the operators with bfs/check_gains.py: w = 0.75 rel 8.4e-16 / 2.1e-16, w = 2.0 rel 3.7e-15 / 4.1e-15. [BFS.md l.58-72]

## 10. Parallelism, MPI and performance

### Do not repeat

- **Do not project parallel round times from LU counts at small n. Read the width of each wave and the serial share of the driver from the ledger.** [mechanism only] STAGE6 §6.30 projected 10-15 min per BFS round on 96 cores. Measured: in the reduced era a pool call held about 9 tasks (23 workers busy 25-37 %, and 95 workers would have been no faster); the driver's own Python took 1000-1600 s a round (50-65 %, job 762583); lattice waves hold 26-64 tasks for 96 ranks. [STAGE6 §6.30 l.1382-1395; BFS.md l.448-449, 547, 605, 787]
- **Do not invest in a GPU port before timing cuDSS on one BFS matrix against 96 CPU cores working on 96 shifts.** [mechanism only] That timing was never done. [STAGE6 §6.29 l.1276-1282]
- **Do not fork after MPI/PETSc initialisation, and do not import mpi4py unconditionally.** [mechanism only] mpipool.active() checks OMPI_COMM_WORLD_SIZE, PMI_SIZE and SLURM_STEP_NUM_TASKS first, because a singleton MPI_Init outside an allocation aborts on the cluster. [BFS.md l.139-149]

### Bugs (symptom -> cause -> fix)

- **A per-process counter cannot see the workers' work: warn, and never report the partial count as the total.** Workers now return their lu_counter deltas. The gate's tracked queries had been uncounted: 4759/1538 became 4741/1555 once counted. [STAGE0 §1 l.31-34; STAGE6 §6.30 l.1304, 1347-1349]
- **Keep instrumentation O(1) per event.** traceback.extract_stack read source lines on every counted solve, 6 % of a round; replaced by a sys._getframe walk. [STAGE6 §6.25 l.753-755]
- **Pin BLAS threads to 1 per process or rank.** Unpinned, a 178x178 eig took 1.9 s instead of 0.03 s (60x); env.sh:84-87 pins them. [STAGE5 §22 l.1052-1055; TRACKER l.510]
- **Re-fork, or ship a settings snapshot, whenever the state workers inherited changes.** fullpar failed with "reshape (8,2)" because the compensator order was set after the warm-up fork, and per-design bases must travel in the task arguments. On the BFS, any new module setting that a task depends on must be an UPPERCASE global of a listed module, or it will not reach the workers. [STAGE6 §6.30 l.1296-1300, §6.33 l.1586; CLEANUP §15; BFS.md l.139-147]
- **Never send the plant through pipes.** A and M were pickled into every continuation task; the plant is now registered once per worker and tasks carry a tag. [STAGE6 §6.28-6.29; BFS.md l.142-143]
- **Diagnostics must not take the expensive path.** `--dump` recomputed sigma on |Omega| = 167 frequencies with the full oracle (167 of the 374 LUs a round). The end-of-run plot cost 2,481 LUs. The lattice end-of-run gain curve was serial: about 1700 factorisations and 37 min on the test plant. [STAGE5 §7 l.445-451, §30.3; TRACKER l.299, 567; BFS.md l.622]

### Decisions

- **Pooled tasks are pure functions of their arguments. 1 task must be bitwise equal to the previous commit, and N tasks bitwise equal to 1 task, except for the winding point count.** This holds for fullpar on GL, and for the MPI task farm bfs/mpipool.py on the BFS (rank 0 drives; 3 ranks bitwise equal to serial). [STAGE6 §6.30 l.1293-1356; CLEANUP §15; TRACKER l.688-690; BFS.md l.139-147]
- **Assign rows to workers by fixed contiguous w-blocks (0.064 wide) so that warm caches stay valid, and keep small batches local** (`--row-workers`, then `--row-workers mpi`). [STAGE6 §6.26 l.810-820; BFS.md l.151-157]
- **Widen certificate generations with `--cert-split` set near the number of workers.** Generation widths otherwise cap the speed-up at about 4x; `--cert-split 32` gave 15x and 12x for 2.3x and 2x the shifts.
  Current code (checked 2026-10-14, HEAD ad580e3; revised 2026-10-14): on the BFS, run_bfs.sh's defaults CERT_SPLIT = 23 ("= the workers") and CERT_NSEG = 16 (bfs/run_bfs.sh:16-17, 98) are sized for 24 ranks. Neither testplant.slurm nor codesign.slurm raises them for 96 ranks. The 96-rank 20261010g runs kept both, against this rule, at a small cost (inference; figures in §20). (corrected 2026-10-14: this entry said "the BFS uses 23" as if that followed the rule.) [STAGE6 §6.30 l.1312, 1329-1330, 1378; bfs/run_bfs.sh:16-17, 98]
- **GL: the row pool and the full-model pool never run at the same time.** (superseded on the BFS: one set of MPI ranks, and the lattice waves mix rows, line and strip.) [STAGE6 §6.30 l.1324-1327; BFS.md l.151-157, 166]

### Process rules

- **Profile one real evaluation, along a real path, under the run's own conditions, component by component.** A synthetic benchmark gave 1.9 s per evaluation, while the run took 6.5-7.8 s (about 700 singular-value computations, about 200 of them golden-section searches). Profile late rounds from a synthetic checkpoint (e.g. mkck.py holding the round-28 working set). [STAGE5 §13.1 l.623-642, §16 l.814-819; STAGE6 §6.25 l.727-744]
- **Time performance runs alone, with identical parallel flags, and normalise per round when the paths differ.** A 6.29 rerun lost `--row-workers 1`, so its 7126 s could not be compared with 5293 s; normalised per round the figures were about 108 s against 110-115 s. [STAGE6 §6.9, §6.26, §6.29 l.1214-1233; TRACKER l.540]
- **Compute the Amdahl bound before adding workers.** `--row-workers` on 2 cores gave 1.29-1.34x, which is the Amdahl limit with rows about 45 %, QP about 22 % and gradient assembly about 8 % of a round; the machine itself scales 1.9x. [STAGE6 §6.26 l.822-840; TRACKER l.651]
- **Separate problem-size effects from parallel effects.** Order 5 rounds were about 7x cheaper, of which only about 1.5x came from parallel rows and the single-thread QP. [STAGE6 §6.27 l.910-914]
- **For large plants, judge cost by factorisations and solves at the measured per-LU cost, not by GL wall time** (a GL LU costs about 1 ms; reduced certification halved the LUs but was slower in GL wall time). [STAGE5 §14 l.691-701, §30.9; TRACKER l.277-280, 295]

### Measured facts

- **Where the time went on GL.**
  90 % of the time was in SQP evaluations, and most of it was wasted: about 6 evaluations per iteration from line searches starting at alpha = 1, 44 % of the iterations refused at the double pole, and the last 5-10 rounds of every run at a stall. An evaluation went 4.6 -> 2.2 -> 0.80 s (follow-scan 0, secant Newton, batching). A big central round took 742 s, 86 % of it in the SQP (rows 44 %, QP 24 %, gradient assembly 14 %). The winding count was 82.7 % of the full LUs of the order-5 run (31,770 of 38,421), and 90 % at ne=100 after §6.29. Full LUs per round went 192 -> 104 after the §30.3 cuts. [STAGE5 §24, §26 l.1342-1351, §28, §30.2-30.3; STAGE6 §6.25, §6.28 l.944-958, §6.29 l.1245-1255; TRACKER l.25-26, 569]
- **The GL pool on 2 cores gains only 1.03-1.06x end to end** (pooled work is 7-10 % of a run at n = 199). On a 2-D model with n = 1,600 to 25,600: sweeps 1.46 -> 1.81x, winding about 1.7x, certificate about 1.55x, enrichment about 1.1x. [STAGE6 §6.30 l.1357-1380]
- **BFS 20261010g utilisation: the mechanisms are in §19 (level set, waves, driver, packing), the figures in §20.** (revised 2026-10-14)

### Open questions

- **Levers not yet tried on equalised plateaus:** lazy evaluation of below-level rows (with a margin re-checked at acceptance), and QP warm start or row aggregation. The witness climb is still serial. (revised 2026-10-14) On the BFS lattice the far-below rows are a small lever, and the followed members' Newton chains and the level set are the larger ones (§19). ## 11. MIMO

### Do not repeat

- **Before interpreting controller structure (diagonal, cross gains), test whether those entries change gamma. In the high-gain regime the controller does not matter.** [clean A/B] The prototype's reading "each sensor is matched to its own actuator" (|D_12|, |D_21| <= 0.03 against 4.2e4) was wrong. T_inf = R - R B (C^H R B)^-1 C^H R does not depend on the controller: zeroing the off-diagonals, or multiplying D_c by 10, leaves 2.3835333. In SISO K+FB+FC, setting C_c = 0 leaves 3.8762964, and T_inf gives 3.8764825. [STAGE5 §34.3 l.2393-2399; STAGE6 §6.17 l.454-487; TRACKER l.639]
- **Do not prototype the optimisation without curvature memory, peak following, Clarke blocks and face S.** [mechanism only] The SLSQP prototype took 30-60 s a round, converged slowly and was refused on sharp peaks. (superseded: its numbers, by STAGE6 §6.20.) [STAGE5 §34.3 l.2375-2417]
- **Do not propose a ||K||_inf bound to shorten plateaus.** [mechanism only] The rows sit in |w| <= 16, where |K| is about 10-300, while |K| peaks at about 5000 near w = 60, where only 40 of the 1225 rows lie. [STAGE6 §6.25 l.773-775]
- **Do not impose or expect actuator/sensor duality in the optimum.** [mechanism only] On GL, A^T = P A P holds exactly, and the dual design has the same gamma to 1e-14-1e-16. The optima are self-dual in SISO and in decentral K+B+C, but not for atoms (distance 0.89). A self-dual start stays on the symmetric set; restricting to it halves the parameters but can miss the optimum. This is GL-specific. [STAGE6 §6.17 l.427-452, §6.24 l.670-680; TRACKER l.638]

### Bugs (symptom -> cause -> fix)

- **Guard comparisons against nan, and test resume for MIMO and SISO separately.** A MIMO start with gamma nan made RESUME/CONTINUE restart from the start and skip the feasible start. [BFS.md l.558]
- See also §5: unstable acceptance outside the band (`--wind-accept`), high-gain branches missed (cert_region_mimo, no tracking), and the INCONCLUSIVE wide band. See §4: false bests (`--band-first`, `--cert-all-w on`).

### Decisions

- **One code path for SISO and MIMO, dispatching on the shapes of b and c** (rank-(m+p) Woodbury, one sparse LU per frequency, winding on f = det(I - K G)). The MIMO class at m = p = 1 equals the SISO class to 1.1e-14 (sigma) and 3.8e-14 (gradients), and `--force-mimo` reproduces SISO to 2.5e-9 over 5 rounds at the same cost. A refactor could make the MIMO path the only one. [STAGE5 §34.3 l.2418-2424; STAGE6 §6.1, §6.16 l.395-423; TRACKER l.637]
- **No MIMO design has r = 0. Static-gain starts keep passive compensator states with C_c = 0, and their poles are closed-loop poles** (the wrong -0.2188 of §6.4 was exactly their real part). [STAGE6 §6.1 l.48-51]
- **BFS 2x2: central order 10, or decentral 5+5. There is no separation constraint between the two ports, which may overlap.** Directories are named _m2p2_<struct>_o10. [BFS.md l.267-273]
- **Every MIMO record gets an independent dense check (tools/check_mimo.py, 7 checks) where its size allows.** The BFS runs use `--dense_check 0`. [STAGE6 §6.2 l.61-82; TRACKER l.616]

### Measured facts

- **Compute the open-loop floor sup_w sigma_{m+1} before judging a MIMO result** (sigma_1 of the closed loop >= sigma_{m+1} of the open loop, pointwise, for a rank-m loop). GL: one pair 3.509193 (1401-point grid), two pairs 2.3835333277 at w = -0.68245; all GL atoms 2x2 designs reach it to 1e-10-1.6e-8. It has not been computed for the BFS (inference: it would show how far the best central record, §20, is from its floor; revised 2026-10-14). [STAGE5 §27 l.1408-1411, §30.11, §34.3 l.2367-2369; STAGE6 §6.9 l.229-237, §6.20]
- **With fixed-shape ports centralisation pays; with shaped fields it buys nothing.** GL K+B+C 5.339317 -> 3.715450 (-30.4 %), with dynamic cross couplings |K_12(iw)| comparable to the diagonal ones; for atoms, 0. BFS 20261010g: consistent so far, central well below decentral (§20), though the decentral comparison design has coincident sensors (§12; revised 2026-10-14). Decentral is a special case of central, so a central result above the best decentral one is a stall (the cold central lattice run gave 472.22 against decentral 547.30). [STAGE5 §34.3 l.2400-2404; STAGE6 §6.9, §6.17, §6.20; BFS.md l.649, 802]
- **Decentral problems are multimodal and path-dependent.** at_dec stalled at 2.964887 on one code version (D_c x 10 gives 2.95996, a flat descending direction) and reached the floor on others. With the second pair started at -+6 or -+9 it stalls at 6.28 (mirror-symmetric); from -+4 it reaches 5.59. Use multistart, and break the symmetry in some starts. [STAGE5 §34.3 l.2405-2410; STAGE6 §6.9, §6.14 l.351-359]
- **High-gain branches sit near eig(D_c C^H M^-1 B), at |w| ~ |D_c| |C^H M^-1 B|** (estimate -1.7-144.7i against true -0.05-156.9i). They caused the far resonances at w = -700 and +409.65 and the band widening to +-1268.9. [STAGE6 §6.4 l.102-131, §6.19 l.535-537]
- **Central optima are equalised plateaus with slow tails.** GL order 16: 788 of 1225 rows within 1 %, 347 sigma_2 blocks, 28 peaks within 1 %; order 5: 202 of 516 rows and 92 blocks; BFS central 191.11 flat on [0, 2.4]. The tail moves about 0.1 % a round. The levers are multistart, budget and a lower order, not stop-rule tweaks. (revised 2026-10-14: the isolated top of job 770632's record, once read as atypical, was a missed peak; its plateau is the usual equalised one, §19.) [STAGE6 §6.15, §6.27; TRACKER l.636, 649; BFS.md l.570-574]

- **A W K S control-cost weight.** It would remove the continuum of gains at the floor (the gains found, 5028 and 42052, are only where the iteration stopped), bound the high-gain branches (W = 49272 and a 378 s level set), and fix the bad scaling of §6.10. ### Do not repeat

- **Do not invest in global position optimisation on the evidence of multimodality alone. First check whether the minima differ in their positions or in their controllers.** [mechanism only] The two GL ne=200 minima share their positions (+-2.335 / +-2.312, against a Gaussian width of 0.4), so the lever there is multistart over controllers. On the BFS the positions move a lot (actuator (0.6, 1.0) -> (1.34, 1.33)) and the two SISO endpoints differ in position (whether they are distinct minima is unproven, §14): re-check before reusing the GL conclusion. [STAGE2 l.127-132; STAGE5 §30.10 l.1845-1846; TRACKER l.83; BFS.md l.531, 802]

### Decisions

- **Ports must be smooth in their position parameters.** The actuator Gaussian is not truncated (sig = 0.5/sqrt(ln 2) = 0.6006, b = M psi_a; it forces the v component by default, `--bfs-act-comp v`). The sensor window is 0.6 long with tanh edges of width 0.05, and the shear trace is exact for P2 (4e-13). [BFS.md l.79-85]
- **Position constraints are hard linear SQP rows with margin `--bfs-margin 0.05`, and a start outside them is refused.** [BFS.md l.103-114]
- **FD-check every port and placement gradient** (SISO 1e-9; MIMO full model 6e-11 to 1e-8, reduced model 5e-10 to 8e-7). [BFS.md l.87, 271, 500]
- **The BFS plant is real: every search, band and certificate runs on w >= 0 (and Im >= 0), and the controller has real parameters (real_ctrl).** [BFS.md l.97-101]
- **Derived bounds must carry the positions they assume** (bounds.py JSON: sensor-limited 9.831865 at xs = 0.98, actuator-limited 9.660137 at xa = -1.03). [CLEANUP §5 l.164-183]

## 13. Fields and regularisation (GL)

The BFS ports are fixed-shape (a Gaussian force and a wall-shear window). These lessons apply if free fields come back.

### Do not repeat

- **Never optimise distributed fields without an explicit, scale-invariant, mesh-independent admissibility condition. Viscosity, normalisation, a truncated basis and a Sobolev preconditioner do not regularise.** [mechanism only]
  The unconstrained 80-mode design gave 3.898938 at ne=100 and 5.520963 on ne=200 (+41.6 %), so it is withdrawn, as is 3.901205. With 160 modes: 3.888738 -> 4.605269 (+18.4 %); the ripple moved to each new cutoff, the flat band extended to +27.7 and |K| grew 321 -> 451. The response to a forcing mode is about 0.72/k^2: the forward map is compact, so rough content is ineffective rather than costly, and the gauge removes the norm cost. The frozen "Sobolev" was a change of variables, which acts only as early stopping under a finite budget. The reading "cosmetic ripple" was wrong: smoothing only the tails costs +34 %. [STAGE5 §28 l.1429-1435, §29.4 l.1589-1615, §32.2-32.3 l.1944-2020, §32.7-32.8; TRACKER l.553, 589-590, 595; CLEANUP §8]
- **An H^1 shape row at kmax = 1 is too weak. Use H^2 (`--field-kmax 1 --field-order 2`) or atoms.** [single pair] H^1 gave 3.895803, still rippled, and +40.4 % on ne=200. H^1 is kept as the atoms' nesting row (at 1.8 in the lattice check, since the parent Gaussian's RMS wavenumber is 1.759). [STAGE5 §32.5 l.2051-2057; CLEANUP §8; TRACKER l.592; STAGE6 §6.31 l.1416-1420]
- **"Atoms beat H^2 with 1/16 of the parameters" is withdrawn. Compare parametrisations from the same start with equal effort, and test whether each optimum is admissible in the other problem.** [clean A/B] (the withdrawal; the withdrawn claim was confounded). From the same start: atoms 3.912595, H^2 3.911740. The atoms' 3.876 came from another start with about twice the effort. A2'' is admissible in the H^2 problem (projection error 4.9e-6, H^2 measure 0.60 < 1), and the mode problem started from it reached 3.868466 in 5 rounds; S2 had stalled in a flat valley (-0.003 % a round). [STAGE5 §32.6, §32.8; STAGE6 §6.36 l.1708-1745]
- **Choose the number of atoms by the re-optimised gamma, never by the fit error, and study capacity by nesting from the best design rather than from a common poor start.** [clean A/B] (one fitted start). The 4-atom optimum lies below H^2 while being 0.16-0.24 away from the H^2 fields. From one fitted start, N = 2 / 4 / 6 / 8 gave 4.914215 / 3.969141 / 3.892286 / 3.887178, and none reached A2'' (3.876296), although A2'' is admissible for all of them. [STAGE6 §6.32 l.1564-1570, §6.34 l.1636-1661]
- **Do not use localised Hermite functions for wide fields, and do not parametrise fields nodally at scale.** [mechanism only] The fields span [-24, 24]: 40 Laplacian modes give 3.4 % error, 70 Hermite functions 7 %. Nodal fields at ne=200 mean about 1,600 real parameters, and the QP cost grows with the square of that number. [STAGE5 §6 l.381-393, §29.4 l.1616-1622]

### Bugs (symptom -> cause -> fix)

- **Orthonormalise ordered bases in an order-preserving way.** _m_orth's SVD scrambled the mode order and invalidated the mode-band analysis of §29.4. Corrected: smooth designs live in the lowest ~50 modes, and the optimised ones put 8.6-10 % of their energy at the cutoff. [STAGE5 §32.1 l.1917-1942; CLEANUP §8; TRACKER l.588]
- **Transfer a design to another mesh as the same function (P2 evaluation, exact re-sampling for atoms), with the driver's own settings, and check the round trip.** Linear interpolation smoothed the content away (4.024146 instead of 5.520963). sob_len 0 instead of 0.8 gave an 18 % field error and a start of 6.18 instead of 3.94. The basis-mode start projected xi as if it were the field (4.805183 instead of 3.927660). [STAGE5 §21 l.1000-1006, §32.3, §32.7; CLEANUP §8; TRACKER l.465-470, 502, 505, 596]
- **A resumed child must reproduce the parent's design in every group, including the groups it newly frees.** FB from B started at 9.9949 against B's 10.1374; FB+FC from FB started at 8.6106 against 9.8694. [STAGE6 §6.31 l.1438-1440; CLEANUP §16; TRACKER l.701]
- **Never start a squared-reparametrised variable at its floor; try a data-driven start too.** The atom fit stalled at a 2e-3 error on a Gaussian of the floor width; starting from the half-maximum width it fits to 1e-12. [STAGE6 §6.31 l.1445-1447; CLEANUP §16]
- **Store reparametrised variables in natural form, with their bounds, and refuse or announce any reinterpretation on read.** A2'' read with a width floor of 0.4 was a different design (field distance 0.56 / 0.57), and nothing flagged it, because the start guard fires only at 10x. [STAGE6 §6.34-6.35 l.1656-1683]
- **Field cases need acceptance winding:** see §5 (the +51.94-20.14i escape).

### Decisions

- **For distributed devices, use a few Gabor atoms with a width floor and a wavenumber cap (4 per field, width >= 1, |kappa| <= 0.7071, with the H^1 nesting row), or modes plus an H^2 row. Choose between them on cost and conditioning. The bounds are modelling choices that should come from device sizes, and they must be stored with the record.** A2'' gives 3.876296, and 3.879283 on ne=800 (+0.08 %); one atom per field sits on both bounds. [STAGE5 §29.4 l.1623-1637, §32.6, §32.8 l.2215-2226; STAGE6 §6.35; TRACKER l.593]
- **In the lattice check, use a width floor of 0.4 and an H^1 row at 1.8, so that the parent's Gaussian is admissible.** [STAGE6 §6.31 l.1416-1420]

### Measured facts

- **Cross-evaluation (the same design certified on a finer mesh, nothing re-optimised).** Smooth start +0.06 %; frozen nodal +0.14 %; H^2 with 80 modes at ne=100 +5.8 %; H^2 with 160 modes at ne=200 +0.31 %; S3 at ne=400 +0.05 %; atoms +0.001 to +0.08 %. ## 16. Process and validation (specific)

### Do not repeat

- **Two solvers that agree at an endpoint do not show optimality when they share admissibility tests, constraint formulations or cushions.** [mechanism only] pyGRANSO reproduced 9.748986, which was the shared cushion artefact. Vary the formulation as well as the solver. [STAGE2 l.207-216; TRACKER l.157, 165]
- **A replay without the loop's state tests a different problem.** [mechanism only] The isolated replay of round 5 did not reproduce the gap. Restore the carried H and radius, the followed set, the screening and Omega (the dumps feed tools/replay_round.py). [STAGE5 §18 l.892-899]
- **Do not record a cause without a replay that reproduces the effect and shows the fix removing it.** [mechanism only] The creep at 7.93 was wrongly attributed to the pair being nearly defective; the explanation was annotated in place. [STAGE5 §28 l.1495-1500]
- **Uncontrolled comparisons confound everything.** [confounded] SQP 7.9379 against pyGRANSO 7.9499 mixed the solver, the oracle, the refinement, the flags and the number of rounds. [TRACKER l.270-276]
- **A default flip without the regression was made once and reverted the same day.** [mechanism only] STAGE1 §12.2 flipped `--select-cons`, `--ctrl-imcap`, `--cont-anchor` and `--inner-maxit 25` on 2026-09-17. STAGE1B reverted them as of the same date, as made "against the handoff's rule", and made every stage-1 script pass the configuration explicitly. This is the precedent behind rule 3 of §18 and the reason the nominal configuration lives in the scripts (§17 item 2). [STAGE1 §12.2 l.394-409; STAGE1B l.31-35; TRACKER l.95]
- **Do not judge a code change by early-round values.** [single pair] From the same zero start, round 2 gave 1244.845 against 1209.568. [BFS.md l.524-527]
- **An import graph alone misclassifies dead code.** [mechanism only] fe_pipeline.py, check_optimality.py and bounds.py were reached through subprocess calls, shell scripts and documented reproducibility chains. [CLEANUP §2 l.34-53]
- **Never patch code with multi-line regexes.** [mechanism only] A non-greedy match deleted CASE_STYLE, BOUNDS and the whole argparse block of plot_results.py. Use bounded line-wise edits, diff every patched file against its backup, and keep migration scripts idempotent. [CLEANUP §6 l.186-196]

About half the cluster allocations up to the end of Stage 0 were lost to unverified changes. [STAGE0 §16.6, §18.3 l.1116-1124]

## 18. Process rules that apply to every change

1. **Search first.** Before proposing anything, grep LESSONS.md, STATUS.md, the STAGE*.md files and BFS.md for the flag, the mechanism and the topic. STAGE6 §6.24 re-proposed a pruning option that STAGE3 and STAGE5 had already rejected.
2. **Invariants after every code change, before any run is trusted:**
   - GL frozen path: case B at ne=100 bit for bit equal to the unchanged code's value in the same environment (required after BFS changes too). That value is **10.23128516441147** in the environments of STAGE0-6 and BFS.md, and 10.231285164411261 in the 2026-10-14 conda-forge sandbox environment (§19). Run the unchanged code first when the environment is new (revised 2026-10-14);
   - witness invariant: 0 violations; Hurwitz selftest: 0 of 200 (tools/check_invariants.sh);
   - SISO identity: tools/check_siso_identity.sh must give 8.754365072650645 with `--oracle-orth column` and the frozen certificate flags, within 1e-7 of siso-v1's 8.754365110002194;
   - tools/check_invocations.py: every invocation passes `--eps`, and no script passes a removed flag;
   - parallel code: 1 task bitwise equal to the previous commit, N tasks bitwise equal to 1 task except the winding point count (tools/check_parallel.py, tools/ab_check.sh);
   - any change beyond tolerance is attributed by reverting one change at a time.
3. **Defaults stay frozen.** New behaviour goes behind a flag. Production scripts pass their full configuration. No default flips without the 27-case regression. The frozen configuration must stay reproducible from one command line.
4. **Verify by execution, never by grep or assertion.** Run a smoke job, execute the guard, run the unit check: FD of every new gradient (per-entry steps), exactness at anchors, dense truth at small n.
5. **A/B discipline.**
   - Same parent record (or the same cold start), same code version, deadline, ranks and flags; change exactly one switch; one directory per arm.
   - Report cost next to value (calls, LUs per component, wall time, ranks busy).
   - Compare round by round across resumes, or at equal wall time on whole gamma(t) curves, and continue both arms past their stops.
   - Budget-match the arms before attributing a cost to a constraint. Put solvers on the same constraint lines.
   - Path spread is about 0.7 % for MIMO and 1-2 % for 4-round runs, and any rounding change moves a MIMO trajectory from round 0. Below those levels, replicate or perturb the start.
   - Never compare across start protocols or meshes without re-certifying.
   - (revised 2026-10-14) Both arms restore the same loop state: start them from one deadline-stopped checkpoint (or the same cold start), never from finished records continued with CONTINUE=1, and check each log's "resume:" line (§15, §19).
   - A change that moves work between ranks is result-identical only if task results do not depend on the rank. That needs `--lattice-driver off` in both arms and a worker-against-worker equality test; driver and worker rows differ by ~7e-13 (§19).
6. **Determinism.** Iteration budgets, fixed ARPACK start vectors and sign conventions, pure pooled tasks, inputs fingerprinted (sha256), BLAS threads pinned to 1. If reruns differ, suspect the inputs before the hardware or the method.
7. **Certification honesty.**
   - Every reported gamma is certified on the full model, at a stated rtol (1e-6), over a stated band ([0, 10] on the BFS, all w on GL).
   - Provisional values are labelled. An inconclusive certificate never accepts.
   - Certificate settings are applied before the start certificate. The witness attains the value.
   - Feasibility (alpha + eps <= 0 at the suite eps) is tested first, and eps is always passed explicitly.
   - Never rank designs below the certificate's rtol.
8. **Convergence claims.** Never from a KKT residual alone, and never from a progress stop with code 4. Rule out the stall mechanisms (compensator pair on the line, carried memory, governor caps, rows not following their peaks). Label budget-limited endpoints "iterates". Cross-evaluate designs on the next finer mesh before quoting them.
9. **Cluster hygiene.**
   - Pass MANIFEST plus version_check; respect the plant ids. `git pull` only in the clone /tmp_user/sator/cleclerc/BFS/codesign, then `bash bfs/stage.sh` and submit from the per-version worktree BFS/v/<label> it prints, never from the pulled clone (20261010j; revised 2026-10-14, §15, §19).
   - Validate inside an allocation, and run a smoke job first.
   - Use a fresh directory, or explicit RESUME/CONTINUE. **Never delete a run directory** (FRESH=1 keeps OUT.old-<date>). Keep checkpoints on deadline stops, with deadlines taken from EndTime.
   - No second mpiexec in a job, except with Hydra's fork launcher on separate CPU halves (`bfs/slurm/pair.slurm`); two jobs of one user never share a sator node; mkdir locks; JIT cache and compiler pinned; the `--comment` line in every slurm script.
   - Read the full log (caught exceptions, FATAL lines, refusals, ledger) before the results.
   - Report through `PUSH=1 bash bfs/report.sh`, and record cancelled jobs.
10. **What every record carries:** the code version and commit, the command line, input hashes, the bounds of any reparametrisation, the certificates written back, the unpacked design (not the packer's z), the termination codes, and a diagnostic marked absent (not zero) when it does not apply.
11. **Memory.** Keep superseded runs under names that say what they showed. Add errata in place and never delete TRACKER rows. Add new lessons to this file. Keep one CLEANUP section per code version.
12. **Refactor.** Follow the protocol in §17: tag and bundle, full closure, move rather than delete, md5 replay identity plus all the invariants of rule 2, MANIFEST regenerated, CLEANUP updated.

### 19.1 Peak following and the in-solve level set

- **When the oracle changes, port every peak-following safeguard: the lattice path lost three that the reduced path had.** Follower windows were not re-centred when the top drifted past the edge (lattice._newton searches base +- 0.1, lattice.py:547; the reduced path searched the full window, STAGE5 §13.1). Shared tops were not deduplicated (FOLLOW_DEDUP needs the reduced oracle, sqp_inner.py:532), and certificate peaks were enrolled at 2^-5 grid points rather than at their tops (run_case_epi.py:1490). In 770632 round 11 the follower, based (inferred: base + 0.1 = 4.13125 forces 4.03125) at a grid point, stopped on its window edge 4.13125 (sigma 143.48, slope +284) while its top 4.180605 stood at 151.4775. Either the edge extension (P3) or the un-lagged level (next entry) alone would have caught it at that design; a cold re-evaluation would not, since a cold start from the base stops on the same edge (verifier). Round 12 would carry three followed members on that one top. [an/missed-peaks.md P3, P4, P5, P6, all VERDICT sound, and VERIFIER (1), (5), missed (8); 770632 r11]
- **Ask the in-solve level set at max(t, smax)(1 + tol), and read every wave's crossings before stopping.** The check asked at t (1 + 1e-4), where t is the epigraph variable, which can lag the rows' maximum (sqp_inner.py:321); a lag of only about 1.3e-4 suffices here. lattice._level then broke at the first wave with a centre above that level, before reading that wave's on-axis crossings (lattice.py:1006-1013). The only part established by elimination is the weaker one: the call broke on a centre region, which it may have filtered or added; the log cannot tell (verifier). So a peak 4.6 % above t passed: the "one active frequency" of 770632 was this missed peak, not an optimum's structure. Replayed at the un-lagged level 144.7887, the check found the region in one wave, though from the 48-centre base grid rather than the cluster's previous cover. The design premise "every row is at most t" (BFS.md l.184) fails under lag, and BFS.md l.723 had recorded this very mode on 2026-10-09. Ask at the rows' maximum: about the same cost, not zero (P1, sound). [an/missed-peaks.md ANSWER, P1, replays 2-3, VERIFIER (2), missed (3); 770632 r11]
- **A wave that confirms one region must not end the search, and a cover can never close around a region above the level.** The crossing branch also breaks at the first wave with a confirmed region (lattice.py:1037-1038), which leaves the cover's gaps unexamined: replay 2 ended with 1.05 of the band uncovered. "Continue the waves while every region is watched" (P2, doubtful) does not terminate. A region above gam has an on-axis eigenvalue at its boundary, so the disks never reach it, and such calls would run to LINE_WAVES = 60 (about 55 min). Exclude watched brackets from the cover instead. `--sqp-refine-max 3` also truncates a call with many regions to its 3 highest. [an/missed-peaks.md P2 verifier, VERIFIER (3), missed (2), (4), (7)]
- **Judge whether a region is watched by the row's value, not by its distance to a member.** missed_peaks drops any region within 1e-3 of a followed member, whatever that row reads (sqp_inner.py:319-322). A row on a window edge or on a lower neighbouring top then "watches" a peak it under-reads. Distance had already failed once, with a fixed member 0.0008 away (20261009b). For a centre region the estimate is the centre's theta, not the top, so locate its crossings before judging it. [an/missed-peaks.md P2 and its verifier; BFS.md §8 20261009b]
- **In-solve level-set additions are not followed after their round, and a centre region is enrolled at its centre, not its top (a probable defect).** They join Omega but not the peak set (run_case_epi.py:3812-3816) and are followed only inside the solve (sqp_inner.py:1684-1686), although the missed_peaks docstring says "followed from then on" (l.310-311). From the next round on they are fixed rows. The final 770632 Omega holds 10 members exactly on the 48 base-grid centres, about 25 on 2^-6 to 2^-12 points, and 0.134766 beside the 0.13 top, while no member sits at 0.132094. So rows under-state drifting tops, the near filter ignores these members, and regions get re-added, feeding |Omega| (116 -> 214). [an/missed-peaks.md VERIFIER missed (1); an/omega-growth.md EVIDENCE "Code"]
- **A certified value above t has two causes: separate epigraph lag from rows that under-state, before diagnosing.** After an accepted step the SQP keeps t = t + alpha dt and raises it to smax only after an in-solve addition (sqp_inner.py:1531, 1656, 1688). When the witness sits on a followed member at distance 0 and the round added nothing, the gap (0.5-1.6 %) is lag. Of the 8 rounds of 20261010g with certified/t - 1 > 1e-3, 3-4 were lag (classified without smax, which is not printed), 2 were followed rows under-reading their top, and 2 were unwatched peaks. All 8 were accepted and still went down, by less than claimed. Three rounds below the print threshold (770632 r4, r6, r7) had in-solve additions, so their excess is rows under-stating, not lag; r6 (3.4e-4) is a real miss above the check's 1e-4 (§20). [an/missed-peaks.md EVIDENCE, P7, VERIFIER (4); an/level-set-waves.md VERIFIER (5)]
- **On the BFS MIMO plateau |Omega| grows because the optimum is equal-ripple, not because far members pile up.** At the final 770632 design, 164 of 214 members lie within 5 % of the last t. The only members below 0.5 t are the 64-point starter grid (w = k 10/63), recomputed at each run's start (here the resumed design) and never removed; 44 of its points remain in 770632. They are 4.8-6.0 % of the MIMO runs' actual row tasks (15 % in SISO no strip) and about 1 % of the wall. A retirement threshold relative to gamma is dangerous on a plateau: 192 of 214 members of the 770632 record sit below 0.95 gamma, though that record comes from its one round with certified/t = 1.046; normal-round records give 33/221, 52/159 and 84/201. Do not delete the starter grid: on GL, losing that coverage made cap-50 fail (STAGE3 §5-6). Screening far-below rows rigorously is possible but nets perhaps 1-3 % of row CPU (P2, doubtful). [an/omega-growth.md ANSWER, P2 and VERIFIER (1), (2), (4)]
- **Followed members locked on one top duplicate their Newton chains; the lattice needs a merge by top.** A followed member without a top yet takes the nearest top of the last evaluation as its hint (lattice.py:792-799), so two members near one top run identical chains all round. The round-end merge compares member keys, not tops, and a member whose top lies within 1e-3 of another is never moved (run_case_epi.py:3884-3897), so duplicates persist. In 770633 the sum of requested Newton points exceeds the evaluation tasks by 25 % (185,237 of 737,161), and by counter-based inference up to about half of its followed members are duplicates. Each puts identical rows in the QP (the near-degeneracy of TRACKER K.3). Merging by top or porting FOLLOW_DEDUP is a cheaper and safer lever than lazy following (P3, doubtful: frozen tops at trials can repeat the under-stated-smax stall of STAGE5 §29.2). [an/omega-growth.md VERIFIER missed (1), P3 verifier; an/eval-waves.md VERIFIER missed (1)]

### 19.2 Stability, the gate and the winding count

- **The k = 1 line cannot see a real eigenvalue right of the line when a nearer one sits left of it at the same Im, so the line's alpha taken alone is not rigorous.** lattice._line keeps one nearest eigenvalue per centre and reports alpha as the maximum it saw (lattice.py:74, 952). A real eigenvalue is hidden exactly when it lies further right of the line than the pin lies left of it: with a pin at -0.0501, -0.04995 is seen and -0.0498897 hidden (verifier's geometry check). The gate's tracker, shifted to lam0 + 0.015, catches hidden reals only on about [-0.0499, -0.0199]. BFS.md l.681 ("Every gamma and alpha reported is rigorous") is wrong for that alpha: the cover proves only that nothing lies ON the line, and the records' alphas (-0.0501042, -0.0501307) are certified only to <= -0.025 by their counts. The SQP calls such an iterate admissible, and the checkpoints and the next round's start rest on the gate alone. A probe at -eps + 0.015 must add only witnesses and rows, never line coverage, or it can produce a false "clear" (G5, doubtful). [an/gate-refusal.md ANSWER, G2 and G5 verifiers, VERIFIER missed (4)]
- **A real eigenvalue pinned at the cushion can cross unseen and cost the whole round at the gate (770633 round 1).** A trial put a real eigenvalue at -0.05002 where its row predicted -0.050100 (l.43). The gate then tracked a watched eigenvalue to the real -0.0498897 at segment 1 (its start lam0 is not logged), the straight-segment midpoint had alpha +0.0183, no prefix was certified, and the tau cap (3.5 against a step of 14) then doubled for 15 rounds. Whether the segment spans a merit excursion cannot be decided, and the mechanism needs none. Round 0's gate certified the tracking onto this round's start, so the crossing most likely arose within segment 1, and -0.0498897 sits just past the pin's mirror point -0.0499, where the line first stops seeing it: both fit the hidden-eigenvalue reading. Both known gate refusals (20261010e and g) are decentral no strip, round 1 (inference: the odd-order loops' real blocks pin several real eigenvalues near -0.05). Nothing was saved: save gate refusals for replay (G2, sound); tools/gate_replay.py is GL-only. [an/gate-refusal.md ANSWER, G2, VERIFIER (1), (2), (4); 770633 l.43, 50-56]
- **"certified prefix: none" does not mean that no certifiable piece exists.** continuation_gate._seg rejects at once when a tracked eigenvalue crosses at the segment's END, with no bisection, so reach is never set. When the midpoint is infeasible it returns before descending into [za, zm] (run_case_epi.py:136-175). Path segment 1 and the 14-long chord of 770633 round 1 were never bisected toward a prefix. A depth-limited prefix search in these two cases fits the `--gate-prefix` design ("one line + one gamma certificate against a whole round"). [an/gate-refusal.md VERIFIER missed (1)]
- **The BFS gate has no exact fallback: enable `--cont-accept-winding` after giving the count an absolute step floor.** The flag has been the GL fallback since STAGE5 §22. bfs/run_bfs.sh has never passed it in any revision; BFS.md l.241 and l.821 document the count-at-start-and-end design and its cost, not a decision against the fallback. A count right of -eps at a design pinned at the cushion is INCONCLUSIVE today: the BFS branch passes no hmin_frac, so the step floor is 1e-6 x min(WT, 4000) = 4e-3 for MIMO and 1e-6 x WT for SISO, against about 1.4e-4 needed. GL's relative hmin_frac 1e-8 does not transfer either (4e-5 for MIMO, about GL's failing floor; 3e-4 for SISO at WT = 30720), so use an absolute floor of about 1e-6, and hint the count with the gate's tracked eigenvalues too. One refusal in 68 rounds is measured. 20261010e had at least one (decentral no strip, round 1), but its total over 103 rounds is not verified: central strip repeats 391.38 in rounds 4-5, cause unknown. The fallback gains at most the refused round (1417 s), only when the count is 0, and the inference above suggests it may well have been >= 1 here; the final-gamma effect is likely 0.1-0.2 %. [an/gate-refusal.md G1, VERDICT sound, and its verifier; STAGE5 §22]
- **Count a resumed run's anchor right of -eps, but never defer the gate on an INCONCLUSIVE count.** On a resume the anchor is only line-verified (run_case_epi.py:3547-3591; "continuation anchor verified: alpha=-0.0501", 770633 l.22), and the parents' records hold counts at -eps/2 only. Stop the run on a conclusive count > 0. On INCONCLUSIVE keep the line-verified anchor and its watch list, because deferring would switch the gate off until the next acceptance (the verifier's correction of G4). It needs the absolute step floor above. [an/gate-refusal.md G4 and its verifier]
- **The BFS MIMO configuration contradicts a recorded rule: no acceptance count, no dense veto, a save-time count without veto, and a gate bounded to the line's band.** That is the GL configuration behind the STAGE6 §6.3 escape. The lattice line covers Im in [0, band] only (bfs/plant.py:325-338; run_case_epi.py:3445), so an eigenvalue crossing at |Im| > band is invisible to the line and the gate. Far-left jumps occur in these logs (770633 round 2: -0.1855 -> +0.0316; round 3: -0.0997 -> +0.1117 at |step| 1.28). A count at every acceptance would cost 5-15 % of a test-plant round and 20-40 min on the full mesh, so keeping it off is a user decision, to be recorded as one. Tracking every watched eigenvalue from a whole ring of offsets in each gate wave (at most 8 tasks for 95 ranks) would widen detection at about zero wall cost and cannot weaken anything. [an/gate-refusal.md VERIFIER (3), missed (2), (3), G5 verifier, OPEN; §5]

### 19.3 Restarts and comparisons

- **CONTINUE=1 from a finished record lost the inner budget, the trust radius and the peak set in five of the six 20261010g jobs, which confounds every comparison across that restart.** Only 770629, which found a genuine checkpoint, printed "resume: inner budget 40, SQP trust 0.16966316168188755, 39 peak members restored" (l.23) and ran 40 iterations in round 0. The other five ran 10 and then 20 iterations in rounds 0-1, from a fresh radius, following only the start's peaks (record histories). The code's own comment (run_case_epi.py:3196-3198) says such a reset "biased every comparison crossing a restart". Only the record write needs the three keys: the reader already picks them up (P6, sound). [an/strip-ab.md VERIFIER; an/omega-growth.md P6 and its verifier; 770629 l.23; §15]
- **The strip question is undecided, but the most informative data lean toward no strip in MIMO; decide it on clean pairs judged at equal wall time.** The clean c/d/e A/Bs were each dominated by a defect fixed since (the cut rule, code 12 and coalescing poles, the LMI's QP failures), so their verdicts say little about the current code. 20261010g's decentral pair is nearly clean all the same (parents 0.26 % apart, both restarted at budget 10), and no strip leads it by 10.7 % at 12.47 h. Central no strip leads by 15 % at 12.62 h despite a 36 % worse parent and no restored budget. ## 21. Lessons of the 20261010n batch and of the 2026-10-16 re-read

Sources: the 20261010n paired batch (branch `results`, folder 20261010n/; BFS.md 8), the verified re-read of every history file (REREAD_2026-10-16.md: 126 conclusions, 41 overturned, 45 to re-test, each verified adversarially, the cheap ones by re-running the measurement), the literature report (LITERATURE.md) and the analyses of the final batch (veto, recovery, idle cores, SISO). Where an entry above contradicts one here, this one is the later evidence; the entries above are not yet annotated one by one (REREAD gives the locations).

### Stationarity and minima

- **No endpoint ever cited as a minimum or as stationary was shown to be one.** [measured] Every one ended on budget-limited rounds (code 4), on premature code-0 exits of `--sqp-stat rel`, or at a fixed point of code later found defective. The BFS SISO "two local minima" 554.97 and 598.11 admit certified descent steps of 0.91 % and 0.83 % (tools/bfs_stationarity.py: gamma(z+d) <= 549.905505 at Delta 1e-4, <= 593.161757 at Delta 1e-5, line clear, positions inside); the 20261008c "fixed point" 145.586 belonged to the basin that reached 123.90 in 20261010n; GL at_dec 2.964887 was a stall that the same start later beat. So the multimodality chain ("multistart over controllers, drop position optimisation", STATUS, LESSONS §11, §14) rests on no demonstrated distinct minimum, and no run ever restarted the positions from elsewhere. Supersedes the "stationary / local minima" readings in §11 and §14, STATUS.md and BFS.md 8.
- **`--sqp-stat rel` is not a stationarity test; use `pred` everywhere on the BFS.** [measured] GL n100 rel: rounds 0-6 exited after 1 iteration, and after rounds 3 and 5, which gained nothing, the next rounds gained 2.4 % and 5.4 %. BFS SISO: code 0 at stat 6-13 against a gradient scale of 1.5e5-2.7e5 (thresholds 15.5 and 27.0) while a 0.8-0.9 % certified step existed; the record's stat_value 6.1 sat against a minimum-norm residual of 2.7e5. pred never exited early in the 95 rounds of 20261010n. 20261010r makes pred the BFS default for SISO too (supersedes §1's "rel stays the SISO default").
- **Normalise a stationarity residual consistently, and lead with the measured first-order decrease in gamma units.** [measured] The GL "stationary kink" 6.2e-4 of KSP+B+C was an artefact of dividing by the MEAN branch-gradient norm (rows 44.1 and 1734.1: the minimum-norm element ignores the large row, the mean is dominated by it); on its participating rows it reads 1.3e-2, like K+B+C's 1.45e-2, which was later beaten by 19 %. The same GL ne=100 residual reads 2.5e-5 (mean), 6.5e-5 (multiplier-weighted) or 1.3e-3 (smallest row), and kkt_residual moves from 2.5e-5 to 0.345 between active tolerances 1e-4 and 3e-5. The one-branch measures (check_optimality, the --dump residual, check_kkt) are not the condition at all and disagree with each other. Report rho over the smallest and the weighted rows, an active-tolerance sweep, and the measured decrease of a step at its validated radius; claim "stationary to x at eps", never a minimum (§4, §18 rule 8). Supersedes the calibration of §4 ("6e-4 reads as a stationary kink").
- **A measure of stationarity is a diagnostic, not a licence to stop.** [measured] GL residuals of 6e-4, 1.5e-4 and 9.6e-5 were followed by 19 %, 2.4 % and 1.3 % more descent; decentral 369.87, read near eps-stationary (rho 4e-4), went 0.7-0.9 % lower in 20261010n.
- **The modal compensator keeps a 2-dimensional similarity gauge per 2x2 block.** [measured on the records] Fixing one B_c entry per row removes only the diagonal scaling (packer.py); 10 of the 60 central and 10 of the 34 SISO variables are gauge. The iterates drifted to ill-conditioned representatives (block cond(V) up to 509 for SISO 554.97, 21.6 for 598.11, 34 for central 123.90, 61 for decentral 412.28), gradient magnitudes span about 200x across variable groups, and the first-order model holds only to about 1e-5 in packed coordinates. The rows and certificates do not depend on the gauge; the metric of every step and every residual does. A gauge rebalance is result-neutral at a point and is the cheapest untried lever on the code-4 crawl (LITERATURE.md idea 3), to be A/B'd.

### Stopping and solver

- **The 3-round progress stop fired again on a MIMO code-4 plateau (20261010n c151 async, 123.904, 0.124 % over 3 rounds).** [measured] Replayed on GL MIMO it would have stopped 0.05-1.90 % high. §1 already said 8 rounds for MIMO and bfs/run_bfs.sh passed 3:0.0015 for every case; 20261010r passes 8:0.0015 for the BFS.
- **"Exchange converged" has never fired: `int(stats.get('termination_code') or -1) == 0` reads code 0 as -1** (run_case_epi.py, since the first commit 718f4e3). [mechanism only] The bug protected the runs from the rel test; fix it only together with pred (fixing it under rel would have stopped GL n100 at 8.969 instead of 6.399).
- **"The inner solve is not the bottleneck, so the solver class does not matter" is false on the BFS.** [measured] In-solve evaluations and the level set are more than 90 % of the wall in 20261010n (GL ne=200 already spent 79 % in the SQP, STAGE5 §28); the premise came from working-set defects. "Do not add another inner solver" (§1) has lost its justification on the BFS, though no alternative has been measured there.
- **The BFS QP failures come from the within-round BFGS matrix, not the rows.** [single pair, two replays] The two distinct failing 20261010n QPs (no LMI) have P eigenvalues up to 5e11-2e12 (condition 5e19-2e20 on its positive part); Clarabel fails with its default equilibration and solves both in 19-35 iterations with equilibration off or bounded to [1e-2, 1e2]. Supersedes "the LMI was the whole cause" as a general account (it was the cause in 20261010e).
- **The trust radius does not control the step on the BFS.** [measured] It is 100-300x the accepted step (radius 0.17-0.70, median accepted step 2.5e-3, alpha 1/256-1/1024), 37-40 of 40 QP steps sit on its boundary, and it grows at alpha = 1 but never shrinks on a partial step, so the line search does all the step control. The SHRINK=1 verdict (§1) was drawn under defects and needs a re-test; with the gauge (above) this is the likely mechanism of the code-4 crawl.

### Stability certificates

- **A rigorous bound can still be unusable: check that a certificate can certify the designs the optimiser will produce.** [measured] The BFS winding count's H^1 tail decays like w^-1/2 while the discrete plant decays like 1/w (w||G|| = 11.74 from 1e2 to 1e7), so the needed tail frequency grew with the square of the compensator feedthrough and passed the hard cap 1e7: the 369.87 record already sat on the last rung (headroom x1.249), every later decentral design raised "tail bound never certifies", and all five decentral arms of 20261010n saved their start designs (half of the batch's 6,927 core-h). A rigorous 1/d bound from the same derivation, computed without factorising the velocity mass (the user's rule), gives W_T 7680 instead of 7.86e6. Log the tail requirement at every acceptance so a cap shows up rounds ahead (20261010r).
- **Never let a fallback overwrite the only copy of a design.** [measured] The veto charged instant pre-march errors against its cap of 3, searched latest-first, fell back to the anchor, and the deadline stop rewrote the checkpoint with it: the five final decentral designs exist in no file. 20261010r writes every accepted design to <tag>_accepted.npz and the final one to <tag>_final_<job>.npz, and charges only real counts.
- **The gamma certificate classifies crossings by a tolerance**: |Re lambda| <= 1e-8 max(1, |lambda|) (certify_sparse.py), and a disk's radius is at least |Re lambda|, so a true crossing computed off the axis is cleared or left in a dropped sliver. [mechanism only] Log the real parts near the axis and sigma-confirm every Ritz value whose real part is below a threshold tied to the sliver tolerance before relying on the certificate at tight levels (LITERATURE.md idea 6). The winding march is validated, not proven (winding_cert.py says so).
- **`--gate-prefix` cannot find a prefix where one is needed** (it returns without bisecting on a crossing at a segment end and on an infeasible midpoint; the path mode supplies a prefix only from segment 2, while most crossings happen at iteration 0). [mechanism only]

### Process and noise

- **Measure path noise on the BFS before judging an A/B at 1 %.** [measured on GL] A 1e-12 start perturbation gives 19.8 % mid-run and 0.014 % at the stop on GL SISO, 9 % mid-run and 0.7 % at the stop on GL MIMO; the 1-2 % floor was never an A/A measurement. The 20261010n strip D moved by 1-3 points within hours. Runs are bit-identical within one code and environment only, which is not insensitivity.
- **The strip A/B (20261010n) ended undecided and is closed by a decision, not by the data.** [clean A/B, 4 pairs, within noise] At equal elapsed time D = -1.37 / +0.14 / -0.13 / -0.59 % (c151, d370, c177, d412); at the jobs' end c177 with the strip was 1.07 % better, c151 without it 0.78 % better. The strip bought no stability (no gate refusal or veto for instability in any arm), cost about 31 % more evaluations per round (not 45 %), and only the no-strip path can use the asynchronous level set (0.71-0.80 of the round wall, identical traces at printed precision over 8 central and 11 decentral rounds). The user's rule (2026-10-16): remove the strip if it is not needed. On this evidence it is not needed (for stability or for the value), so 20261010r removes it from the optimiser; its eigenvalue search stays as a diagnostic. That it is never better is not shown: reopening needs a BFS A/A first.
- **Async identity is at printed precision, not bitwise**: the synchronous arms compute rows on rank 0, the async arm almost nothing there, and driver and worker rows differ by about 7e-13 (§10). [measured] A worker-against-worker bitwise test is still owed before calling them identical; async also slows identical work by 7-17 % on a shared node.
- **Extrapolations from small scale failed at production scale.** [measured] Winding counts run at 15-21 % efficiency on 48 ranks (one segment sets the wall); evaluations cost 3.5-14x the projections; the full mesh needs about 25 GB per rank for the lattice (about 20 ranks per node, which codesign.slurm's defaults cannot hold) and was never optimised or plant-certified.
- **Report the cost of a lost job, not only its values**: the half-node of 774364 sat idle 1.8 h after its arm's progress stop (pair.slurm runs a queue of arms from 20261010r), and the decentral arms' 3,448 core-h bought nothing saved.
